Skill may say (version-pinned; the 'otel-ruby' versions above):
1. In opentelemetry-instrumentation-rack 0.31.2, the server span carries the full query (`url.query` under stable semconv; `http.target` including `?query` under the deprecated `http/dup` and `old` modes). No option disables it, and `url_quantization` only affects span names. If query strings can carry personal data, drop or redact them in a SpanProcessor or exporter wrapper; an attribute allow-list is the safest design. Say that the allow-list wrapper is Retask's chosen design, not the only way.
2. In action_pack 0.18.1, `c.use "OpenTelemetry::Instrumentation::ActionPack"` installs Rack instrumentation and inserts the Rack middleware at position 0 through its railtie. Do not insert it again. Guard it with a spec asserting exactly one middleware entry carrying the OpenTelemetry handler. The earlier "insert it yourself" advice is wrong and must not be written.
3. `c.use "OpenTelemetry::Instrumentation::Rails"` installs nothing itself (`install { true }`). Use `c.use_all`, or `c.use` each component (ActionPack, ActionView, ActiveSupport, ActiveRecord, ActiveJob). A request span needs ActionPack.
4. With otel-api 1.11.1 and sdk 1.13.1, ids come from `Random.bytes`, so they consume the `srand`-seeded sequence and make seeded specs non-deterministic. Set a custom `id_generator` (any object responding to `generate_trace_id` and `generate_span_id`, built on `Random.urandom`) through `OpenTelemetry::SDK.configure`; this is the sturdier alternative to prepending on `Trace`.
5. In pg 0.37.0, every query yields a span, and prepared statements yield separate PREPARE and EXECUTE spans, both carrying the obfuscated statement. Filter by `db.operation` (and `db.collection.name` or the statement text for `pg_` catalog queries). There is no "SCHEMA" name. With the default `db_statement: :obfuscate`, literals become `?` and `$n` becomes `$?`. Flag the catalog-lookup noise as observed, not source-verified.
6. WebMock replaces `Net::HTTP` with a subclass that returns stubbed responses without calling `super`, so stubbed requests are not instrumented. To assert on a client span, allow a real loopback connection (`WebMock.disable!` or `allow_net_connect`). General doctrine for any WebMock suite.
7. `start_span(start_timestamp:)`, `finish(end_timestamp:)` and `add_event(timestamp:)` take a Time or a Numeric in seconds (sdk 1.13.1 does `to_r * 1e9`), never nanoseconds.
8. From Ruby 4.0, `benchmark` is a bundled gem, not a default gem, so it must be in the Gemfile under Bundler (`bin/rails runner`). Add the Ruby 4.0 NEWS link before shipping.
9. Code an initializer needs must not be in `autoload_lib`'s reloadable paths: use `config.autoload_lib_once`, or put it under an `ignore:`d directory and `require` it (Rails autoloading guide). The "namespace that does not collide with `app/models`" tip is Retask-specific and unverified.
10. The SDK catches exceptions from an exporter or processor and reports them via `OpenTelemetry.handle_error`. SimpleSpanProcessor logs "unexpected error in span.on_finish"; BatchSpanProcessor swallows exporter errors and returns FAILURE with an `otel.bsp.error` metric. A custom exporter's bug therefore appears as missing spans, so unit-test the exporter directly.
