Which parts of the toolchain work on every stack

Generated by scripts/component_classes.py from docs/architecture/rails-assumptions.policy.json; do not edit. python3 scripts/component_classes.py --check fails when this page is stale. Issue #2192, under the nextjs-stack epic #2162.

How to read this

Every hook, command, agent, skill, script and gate we ship is listed once, under the plugin it ships in, with one class:

  • neutral works the same on any stack. A scan of its text finds no Rails or Next.js reference.
  • rails exists only for Rails projects. It will move into the rails-stack plugin; the issue that moves it is named.
  • nextjs exists only for Next.js projects.
  • mixed stays where it is but still assumes a stack somewhere. The seam says where it will ask the stack detector instead (or that it is only wording), and the issue is the plan step that fixes it.
hook
a script the assistant runs automatically at a moment in a session (before a command, when it stops) to block or warn.
command
a /name a person types to start a workflow.
agent
a specialist the assistant hands one job to, with its own instructions.
skill
a folder of written guidance the assistant loads when a task matches.
script
a program that does the checking or generating work behind the rest.
gate
one check that must pass before work moves on; each is a row in a plugin's checks.json.
seam
the place a stack-specific step will be swapped for one the stack provides.
stack detector
the shared code (#2163) that looks at a project and answers which stack it uses and which commands and paths to run.
policy file
docs/architecture/rails-assumptions.policy.json: where each decision and class is written down.
scan
a search of every file's text for Rails and Next.js names, run by component_classes.py.

The class is written down once, in the policy file, and the scan checks it: a component marked neutral that names a Rails or Next.js thing fails the check, and so does a component nobody classified. Limit: the scan finds references by name. A component that assumes Rails without ever naming it still reads as neutral, so neutral means “nothing found”, not “proven on every stack”. The per-file reasons are in docs/architecture/rails-assumptions.md.
