## setup-flow, section by section (issue #2180)

/rails-flow:setup-flow is the shipped home of a project's working rules (git flow, guardrails, parallel sessions, labels, who merges). Today it reads the Gemfile, the Rails version and the rails-8 skill to fill them, and the second half of the file is a list of Rails-only repairs. The rule scaffold itself names no stack; the stack facts and the Rails repairs are what assume Rails.

| lines | Rails hit lines | what it assumes | decision | how |
|---|---:|---|---|---|
| 41-74 | 8 | diagnoses a CLAUDE.md against the Gemfile, the Rails generator and the Ruby/Rails version; inspects Gemfile, config/application.rb, db/schema.rb and app/ shape | `detector` | reads the facts from the detector's descriptor (stack names, versions, directory shape) instead of opening a Gemfile |
| 144-212 | 7 | the CLAUDE.md template: a Rails/Hotwire/Solid Queue/Kamal stack line, the Rails command list (rspec, rubocop, brakeman, bundler-audit), the simple_form forms rule, the bundler.lock preflight line | `detector` | the stack line, command list and forms rule are filled from the stack descriptor; the Rails text becomes the rails-stack template |
| 259-362 | 8 | path-scoped rules over app/models/**/*.rb and **/*.rb, config/database.yml as the database marker, config/ci.rb and bin/ci, and the one RAILS_ENV=test bin/rails command guard-bash allows | `detector` | globs, database marker and the allowed test-prep command come from the descriptor |
| 524-694 | 12 | companion workflows: bundle exec rspec, rubocop, bundler-audit, brakeman, the architecture graph over routes/app/db, derived docs over db/schema.rb and Gemfile.lock, the help registry rake task | `detector` | suite, lint and security commands come from the descriptor; the graph and help registry are the rails-docs-generators move |
| 731-1144 | 72 | Rails-only repairs proposed as approved diffs: the config/ci.rb Tests steps, RSpec generators and factory_bot_rails, i18n and launch initializers, the privacy inventory over db/schema.rb, the tenancy cop, simplecov, spec/support wiring, simple_form, Archspec.rb and herb | `rails-stack` | moves to rails-stack's own scaffold; setup-flow runs the section for each stack the detector reports |

**Proposal for a `nextjs-stack` repo.**

- Split the file by who owns the content: the stack-neutral rule scaffold (git flow, guardrails, parallel sessions, labels, who merges) stays in rails-flow's setup-flow and names no stack; each stack plugin ships its own scaffold section.
- setup-flow asks the detector (#2163) which stacks the repository holds (more than one is allowed), fills the stack line, commands, source globs and database marker from the descriptor, and then runs each stack's section in turn.
- For a nextjs-stack repository that means: the same rule scaffold; stack facts from package.json, next.config and supabase/ as the detector reports them; and nextjs-stack's section proposing its own repairs (strict TypeScript, Storybook, local-first CI) as approved diffs, the way the Rails repairs are proposed today.
- A project's rules arrive by running setup-flow, not by a hand-written copy: a repository adopting the rules (flo-it-ui, for one) gets the neutral scaffold plus its stack section, and a later release updates it the same idempotent way.
