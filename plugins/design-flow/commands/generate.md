# `/design-flow:generate`

Produce a tier-3/4 asset (illustration, decorative art) for one surface.

**Most runs of this command should refuse, and that is the design.** Generation is the last resort
in the asset hierarchy, it costs real money, and every cheaper tier is checked first. A run of this
command that always approves has been mis-wired.

## Before anything else: is this reachable?

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/generation_gate.py" --request request.json
```

Exit **0** approved · **1** refused, with the reason · **2** unusable request or config.

**Print the refusal reason verbatim and stop.** Do not paraphrase it into "generation isn't set up",
do not offer to improvise an asset, and never ship a placeholder. Refusal is a complete answer here.

## 0. The library comes first, and it is seeded once

**Do not generate assets one at a time as surfaces come up.** That produces a pile, not a set — each
piece defensible alone and the family incoherent, which is the look this whole path exists to avoid.

Seed the library **once the PRD has been converted into skills and the product intent is understood
— before any coding begins.** That timing is the point: the brief is settled, so the set can be
curated against what the product actually is, and every surface built afterwards reaches for an
asset that already exists instead of commissioning one mid-build.

The seeding pass:

1. **Read the PRD and the skills it produced.** What the product does, who for, what it feels like.
2. **Brainstorm broadly, then cut.** Several directions, one chosen — a coherent family sharing a
   style, palette and level of abstraction, not eight good ideas in eight styles.
3. **Cover the surfaces the product will actually have**, static and motion together. A looping
   accent is a separate artefact from the still it animates, so decide which surfaces get both.
4. **Write the manifest** (§0b), then generate — each asset through this gate, cheapest rung first.

Everything after seeding is **top-up**: an agent hits a surface the set does not cover, records the
miss, generates one asset, and appends it to the same manifest. The library grows by coverage, never
by duplication — the gate refuses a request whose surface and kind the manifest already lists.

## 0b. The manifest is a reference table, not an inventory

`docs/assets/manifest.json`, beside the assets themselves. It exists to answer the question an agent
actually asks — *may I put this here, and will it look right?* — so a row that only names a file is
useless: the asset gets re-generated by whoever could not tell.

```json
{
  "assets": [
    {
      "file": "docs/assets/hero-lattice.svg",
      "name": "Hero lattice",
      "purpose": "carry the marketing hero before there is product UI to screenshot",
      "use_cases": ["marketing hero", "docs landing header"],
      "avoid": ["anywhere beside a product screenshot — the two read as competing focal points"],
      "visual_elements": "interlocking woven bands, single ink weight, no gradient",
      "style": "minimalist-ink",
      "kind": "static",
      "surface": "marketing-hero"
    }
  ]
}
```

Every field is required, and the checker enforces it:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/generation_gate.py" --check-library docs/assets/manifest.json
```

**`avoid` is the one people skip and the one that matters most.** Without it a curated family drifts
by well-meaning reuse — one reasonable-looking placement at a time — and afterwards nobody can point
at where it went wrong. `use_cases` must be non-empty for the same reason: an asset with no stated
home is one nobody will find, so it gets bought again.

## 1. Rule out the free tiers first — in writing

The hierarchy decides this; you do not:

| tier | what it is | costs? |
|---|---|---|
| 1 | product screenshot (Playwright capture) | **no** — the product *is* the asset |
| 2 | brand-geometric decoration built from `brand.json` | **no** — CSS/SVG from tokens |
| 3/4 | illustration | **yes**, and it is last on purpose |

`visual-assets.md` §6 already makes tier 2 + expressive type **primary** on surfaces with nothing to
screenshot. So the request must record, per surface, why **each** free tier cannot carry it:

```json
{
  "tier_refusal": {
    "surface": "marketing-hero",
    "tier_1_why_not": "pre-launch — there is no product UI to capture yet",
    "tier_2_why_not": "geometry reads as filler at hero scale on this pack"
  },
  "pack": { "palette": ["#0b0b0c", "#f7f7f8"], "type": "Inter", "variant": "default" }
}
```

Both `*_why_not` keys are required. An unstated tier is an unexamined one, and it costs nothing to
examine — so the gate refuses rather than assuming.

## 2. Do not write the prompt

The gate composes it from the surface class, the aesthetic brief for that class, and the pack. A
`prompt` key in the request is **rejected**, not ignored — silently dropping it would let you
believe your text was used.

This is not stylistic. An improvised prompt produces the stock-art look `visual-assets.md` warns
about, and **it pays twice**, because a vague prompt is a reroll. The composed prompt is also what
makes the asset reproducible: without it, a brand change means paying again.

## 3. Configure the ladder and the ceiling in the project, not here

`.design-flow/generation.json`:

```json
{
  "aggregator": "<your aggregator>",
  "budget_usd": 5.00,
  "ladder": [
    { "name": "<cheapest model>", "cost_usd": 0.012 },
    { "name": "<next rung>",      "cost_usd": 0.40  }
  ],
  "style_reference": "brand/illustration-reference.png",
  "briefs": {
    "marketing-hero": {
      "style": "minimalist-ink",
      "subject": "an abstract woven lattice",
      "mood": "calm, precise"
    }
  },
  "acceptance": {
    "marketing-hero": "reads as the brand at a glance; no stock-illustration tells"
  }
}
```

**Model names and prices are not doctrine.** They change monthly and a list in a skill would rot
inside a quarter, so they live in project config and this command names only the contract: a ladder,
cheapest first, climbed **only** when the output fails a stated acceptance check.

A surface with no `acceptance` entry is **pinned to the cheapest rung**. That is the whole of the
rule — without a stated check, "the cheap model wasn't good enough" has no trigger and *best output*
collapses into *the agent liked it*.

## 3b. `style` is required, and it is a closed set

A brief that says only *"calm, abstract"* is not a specification. Mailchimp's illustration is
monochrome ink line-work on a saturated brand ground; Headspace's is flat vector with rounded
characters, no outlines, faces reduced to two dots and a curve. **Both are on-brand — for different
brands**, and a mood-only brief can produce either. Two runs against one pack then drift apart, and
the second one is a reroll nobody planned to pay for.

So `style` must be one of: `minimalist-ink`, `flat-vector`, `character-world`, `geometric`,
`vintage-rustic`, `3d-render`, `cartoon`, `mixed-media`. The gate refuses anything else, for the
same reason it refuses a free-typed prompt.

Two consequences worth acting on:

- **`geometric` is usually tier 2, not tier 3.** If the style you want is constructed from
  primitives, build it from `brand.json` tokens as CSS/SVG and pay nothing. Check this before
  writing the tier-2 refusal, not after.
- **Let the ground do the branding.** In the strongest examples the drawing is monochrome and sits
  on a brand-coloured panel — the panel is CSS. Generating line art rather than a full-colour scene
  is cheaper, survives a pack swap without re-generating, and is markedly easier to keep consistent.

## 3c. What the aggregator must support

The contract, not the vendor:

1. **text-to-image from a composed prompt** — the baseline;
2. **a style reference image** — the single biggest lever on consistency. Give it one approved
   asset and new work matches its palette, line weight and shading rather than re-rolling the look
   each time. Point `style_reference` at that file;
3. **a per-request price you can read before calling**, or the budget ceiling is guesswork.

Any provider meeting those three is swappable by editing this config. As of 2026-08, Google's
Gemini image models satisfy all three and expose a genuine cheap-to-premium ladder —
`gemini-3.1-flash-lite-image` and `gemini-3.1-flash-image` (Nano Banana 2 / 2 Lite) below
`gemini-3-pro-image` (Nano Banana Pro), with reference-image support across the range
([model IDs](https://ai.google.dev/gemini-api/docs/image-generation), checked 2026-08-08). **Those
names are an example, not doctrine** — put them in this file, never in a skill, because prices and
IDs change monthly and a list in doctrine rots inside a quarter.

For icons and flat shapes, prefer asking a **text** model for raw SVG over generating a raster: it
scales, it diffs, and it recolours from tokens.

## 4. No aggregator? Say so and stop

The default install has none, and that path must work. A shipped plugin cannot depend on an MCP
server or an API key being present, so with nothing configured the gate refuses and you report it.
Satisfy the surface from tiers 1–2 or leave it unfilled — those are the only two options.

## 5. Record the provenance row

On approval the gate returns one. Write it beside the asset, in the §Provenance table:

```json
{ "surface": "…", "model": "…", "cost_usd": 0.012, "prompt": "…", "pack_variant": "default" }
```

Every field earns its place: without `prompt` the asset is unreproducible, and without `cost_usd`
the budget cannot be reconciled against what was actually spent.

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/generation_gate.py" --selftest
```
