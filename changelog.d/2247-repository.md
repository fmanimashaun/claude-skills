- **The committed generated pages hold no aggregate, so unrelated PRs stop conflicting on them — `scripts/component_classes.py`, `scripts/rails_assumptions.py`** (#2247). Every PR that added or reclassified a component rewrote the same count lines (`summary`, `by_class`, `by_plugin`, "Totals", the decisions and flows tables), so each landing PR made every other open PR DIRTY and cost it a dev merge, a rebuild and a 12-minute `gates` run. Measured on 2026-10-21 on three DIRTY PRs: 40 of 48 conflict hunks were aggregates. `component-classes.json` and `rails-assumptions.json` no longer carry `summary`; `component-classes.html` counts its own rows in an inline script when it is opened; `rails-assumptions.md` drops its counts table and points at `python3 scripts/rails_assumptions.py --status`, which now also prints the per-flow counts. A move's file list is one file per line. The per-entry data is unchanged and `--check` still refuses a stale page. Each selftest asserts the invariant that adding one component or file changes only its own lines, and `component_classes.py --selftest` runs the page's script in `node` and compares its totals with `summarise()`. An aggregate-free page is the (b) option of the issue; generating without committing (c) stays the owner's decision if per-entry conflicts still serialise merges.
