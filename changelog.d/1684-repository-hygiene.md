- **`claude plugin validate --strict --json` is a doctor gate, and `/gauntlet` says how to try a changed plugin in a real session — `scripts/check_plugin_validate.py`, `scripts/mutations/check_plugin_validate.py`, `scripts/maintainer_doctor.py`, `.claude/commands/gauntlet.md`, `docs/evidence/upstream/claude-code.json`** (#1684). The CLI is the authority on what Claude Code accepts; measured on 2.1.296 it passes the marketplace and all four plugin directories, about a second each. The gate runs it over the marketplace and every local plugin source the marketplace lists (`skills/` is not a target: a run over it reads no manifest and returns `contents: []`, a pass over input it never read), and it refuses to call a result a pass unless the exit code, `success`, `strict` and a read manifest all agree. It exits 3, a SKIP, when `claude` is absent or older than 2.1.259 (the first with `--json`), as on a runner without the CLI; it complements `check_frontmatter.py` and does not replace it (#1679: the CLI passed an unterminated `tools: [Read` list). Flags verified against https://code.claude.com/docs/en/plugins/cli-reference on 2026-10-10 (`--strict`, `--json`, exit codes 0/1/2, `--plugin-dir` and the folder-of-plugins form) and `claude plugin validate --help` on 2.1.296; three quotes are registered for the weekly re-read.
