section: rails-flow
- **guard-bash's issue-label check follows a `cd` across a heredoc body, says "cannot tell which repository" when it cannot follow one, and no longer refuses `bash -n` — `plugins/rails-flow/hooks/scripts/lib/issue_labels.py`, `plugins/rails-flow/scripts/check_hook_gates.py`, `scripts/mutations/hook_issue_labels.py`** (#1851). The issue said the check read the session's `.rails-flow/issue-labels.json` instead of the target repository's. The coordinator measured the installed 1.58.0 first and found it narrower, and this reproduces it: a single-line `cd <other> && gh issue create …` already answered to the target repository's declaration (also with `~` and `-R`); the failure was a `cd` followed by a MULTI-LINE command, the doctrine's own shape (`cd <repo> && cat > body.md <<'EOF' … EOF` then `gh issue create` on a later line), which the hook judged by the session's rules and refused naming the session's taxonomy (`needs one of comp:*`), which read as "the target repo was ignored". Three fixes. (1) The cd now stays in force across segments that only write a file with `cat > PATH` (no `$` or backtick in the path, no `.git` component, so nothing can move gh's target), so the heredoc-then-create shape is judged by the target's declaration, and still refused by it when the labels fail. (2) A `cd` the hook cannot follow (another shape, a subshell, a command between the cd and the create) is still refused, which cannot leak, but the refusal now says it cannot tell which repository the create lands in and to run `cd <repo> && gh issue create …` on one line or use `-R`, instead of quoting the session's taxonomy; a cd that was followed and then fell back for want of a certain target, a named repo and a `cd` that is not a command keep their own wording, and 23 older checks now assert the new wording. (3) `bash -n script.sh` (and a clustered `-nv`) parses and executes nothing, so a create inside the script is text and is allowed; `bash script.sh`, `bash -x script.sh` and an `-n` after the script name (its own argument) are still refused. Fixtures through the real hook: a create after `cd <other>` and a heredoc body (allowed, and refused by that repo's rules when under-labelled), an unfollowed cd, `-R other/repo`, and `bash -n` against `bash` of the same script; 13 new module checks (and 23 older ones updated); ten mutations, one of which restores the session-cwd read, each replayed against the module's selftest and caught. Our own hook; no framework claim.
