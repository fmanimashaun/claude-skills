- **guard-bash's issue-label check follows a `cd` across a quoted heredoc body, says "cannot tell which repository" when it cannot follow one, and no longer refuses a plain `bash -n` — `plugins/rails-flow/hooks/scripts/lib/issue_labels.py`, `plugins/rails-flow/scripts/check_hook_gates.py`, `scripts/mutations/hook_issue_labels.py`** (#1851). The issue said the check read the session's `.rails-flow/issue-labels.json` instead of the target repository's. The coordinator measured the installed 1.58.0 first and found it narrower, and this reproduces it: a single-line `cd <other> && gh issue create …` (also with `~` and `-R`) already answered to the target's declaration; the failure was a `cd` followed by a MULTI-LINE command, the doctrine's own shape (`cd <repo> && cat > body.md <<'EOF' … EOF` then `gh issue create` on a later line), judged by the session's rules and refused with the session's taxonomy (`needs one of comp:*`), which read as "the target repo was ignored". Three fixes, scoped to honest shapes (the hook is a tripwire for honest mistakes, #1793, not a model of steering). (1) The cd stays in force across a segment that only writes a BARE relative filename with `cat > NAME` (no `/`, `~`, `..`, `$` or backtick, nothing starting `.git` in any case) under a QUOTED heredoc; an unquoted heredoc (its body substitutes `$(…)`), a path in a directory, the home directory or another absolute path loses the cd, so the heredoc-then-create shape is judged by the target's declaration and still refused by it when under-labelled. (2) A `cd` the hook cannot follow is still refused, but the refusal says it cannot tell which repository the create lands in and to run `cd <repo> && gh issue create …` on one line or use `-R`, instead of quoting the session's taxonomy; 23 older checks assert the new wording. (3) `bash -n script.sh` (and `-nv`) parses and executes nothing, so a create inside the script is text and is allowed, but only when no option word before the script starts with `+` (`bash -n +n s.sh` turns noexec off and EXECUTES the script, found in review) and none is `-o`/`+o` or a cluster holding `o`; `bash script.sh`, `bash -x script.sh` and an `-n` after the script name stay refused. Fixtures through the real hook (a create after `cd <other>` and a quoted heredoc body, allowed and refused by that repo's rules; an unfollowed cd; an unquoted heredoc; a write to `~/.gitconfig`; `-R`; `bash -n`, `bash -n +n` and `bash`) and 29 module checks; 17 mutations replayed against the module's selftest, all caught (one mutant exposed an unguarded heredoc strip in the verdict, now fixed). Our own hook; no framework claim.
