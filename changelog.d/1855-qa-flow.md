section: qa-flow
- **A requirement-to-case gate: every requirement is named, by id, in an ACTIVE catalogue case — `plugins/qa-flow/scripts/check_requirements.py`, `plugins/qa-flow/scripts/mutations/check_requirements.py`, `plugins/qa-flow/checks.json`, `plugins/qa-flow/commands/cases.md`, `plugins/qa-flow/commands/setup-qa.md`, `plugins/qa-flow/scaffold/qa/requirements.yml`** (#1855, slice 1 of #1853). Owner rule 2026-10-11: "we should have 100% test case"; downstream, 0 of 426 registry requirements were named by any of 923 cases. The gate reads a registry (`qa/requirements.yml`, one `key: <JSON value>` per line, no YAML library) and the catalogue, and fails a requirement no ACTIVE case names in its Source column unless it is on a baseline that may only shrink (size header, a now-cased line is itself a finding, `--base REF` refuses growth, an unreadable ref is exit 2). The registry's `# rows: N` header must equal its entry count (a requirement cannot be deleted with its baseline line unseen), the shipped `checks.json` entry runs `--base origin/dev` and a base with no baseline file skips the growth check with a printed note, the catalogue is read as UTF-8 with a BOM tolerated (an Excel save), and a `requirements:` path outside the project is exit 2. A deprecated or draft case covers nothing, an id inside a longer token does not match, and a Source that names a mistyped requirement id is a finding. Stack-neutral generalisation of Retask `scripts/prd_requirements.py` (Retask #1578); paths come from a `requirements:` section of `qa/qa.config.yml` or default to `qa/`. `--uncased` lists what `/qa-flow:cases` must author. Shipped as a `checks.json` entry, a scaffold, and a doctor gate for its selftest; twenty mutants, each caught by the row that names it. Our own design on the owner's decision recorded on #1853; no framework claim.
