section: rails-flow
- **The brain is enforced, not nudged — `plugins/rails-flow/scripts/check_brain_fresh.py`, `check_owner_rulings.py`, `docs_layout.py`** (#2297, #2298). (1) `brain-fresh` refuses an arm or a promotion while `docs/brain/STATUS.md`'s `_Updated: <date> · sha` commit is older than the newest `v*` tag; it fires only at an arm (a `chore/arm-*` or `release/*` branch, or a diff adding a `(release vX.Y.Z)` heading) and is not applicable otherwise; at an arm it refuses, never passes, when it cannot tell (no STATUS, an unreadable line, a sha the clone lacks, a shallow clone). (2) `owner-rulings` refuses a PR whose `Fixes #n` issue carries an owner ruling (`owner rule/ruling/decision/decided/direction`, or `owner, <date>`) when no `## D-NNN` block in `docs/brain/DECISIONS.md` mentions `#n`; with `gh` present a failed read refuses, and it is not applicable only where `gh` is absent or the branch has no PR yet, said plainly. (3) `docs_layout.py` now requires `brain/`, `product/`, `architecture/` and `evidence/` in every project (and `design/` with a UI, `runbooks/` with a deploy), accepts a reasoned `## Waivers` row in `docs/README.md`, and refuses a waiver with no reason, for a directory that exists, or for a name outside the layout; `--scaffold --write` creates the missing ones. Both new checks are registered in `plugins/rails-flow/checks.json`, so a project's sweep (and `gh pr ready` behind it) runs them. A project is checked only where `project_gates.py` is wired into its CI or `CLAUDE.md` (setup-flow §8), which is why flo-it-ui, which never was, reported nothing; setup-flow now says so.
