section: Repository hygiene
- **The mutation harness keeps the mode of a staged `needs` file, so the `git_shim` and `git_shim_hook` guards are no longer INERT — `scripts/mutation_check.py`, `scripts/mutation_check_selftest.py`, `scripts/mutations/mutation_check_harness.py`** (#1893). The v1.156.0 sweep reported both guards INERT: their unmutated selftest failed in the staged tempdir ("env file NOT written", `command -v git` printing `/usr/bin/git`, `git reset --hard` changed the repository). It was not the shim and not #1862's trusted-env lib: measured on dev with the real SessionStart hook, the hook writes the shim line and `command -v git` names the shim, and the selftest passes (314 checks) when its files are copied with `shutil.copy`. `stage()` copied a `needs` file with `shutil.copyfile`, which copies the bytes and drops the mode, so `git-shim/git` was staged without its executable bit: the hook's `[ -x "$CLAUDE_PLUGIN_ROOT/git-shim/git" ]` was false and a fixture that execs the shim ran the real git. `stage()` now calls `shutil.copymode`. The selftest has a row for it (an executable file stays executable, a plain one stays plain), and a mutant removes the call. Verified: `mutation_check.py --guard git_shim_hook` 3 of 3 caught and `--guard git_shim` 47 of 47 caught on this branch. Our own design; no framework claim.
