section: Repository hygiene
- **The `maintainer_doctor` guard is judged again: check A of `scripts/maintainer_doctor_selftest.py` no longer depends on where the tree sits** (#2332). Since #2315 the guard was INERT on macOS and on Linux ("the UNMUTATED selftest already fails in the staged tempdir"), so every doctor mutant was unjudged and the next release's mutation shards would have failed on it. Cause, reproduced on this Mac and read in the shim source: the shim accepts a marked fixture only when its temp root does not contain the session's project (`temp_root_ok`), and check A took the machine's temp root for `TMPDIR` while the harness stages the tree under that same temp root (`mutbase-<guard>-*`), so the check passed in the real tree and failed in the staged copy. Check A now takes a fresh `TMPDIR` subdirectory of its own, which cannot contain the tree wherever the tree sits, and the selftest runs it a second time for a project placed inside the temp root, so the real tree can no longer hide the bug (with the old `TMPDIR`: 0 failures in the real tree, 2 in the staged run). Measured: `mutation_check.py --guard maintainer_doctor`: 50 of 50 caught on macOS (496 s) and on Linux through `scripts/linux_check.sh maintainer_doctor` (251 s).
