section: Repository hygiene
- **New doctor gate: every exit 3 a shipped check can give has a selftest row saying why it is not applicable — `scripts/check_exit3_rows.py`** (#1873). `project_gates.py` grades exit 3 as n/a, which never fails a run, so a 3 that means "could not look" passes silently (#1864, #1867, #1872). The gate parses each `checks.json` script with `ast`. A site is each `return` or exit call (`sys.exit`, `exit`, `SystemExit`) whose value can be 3: a literal, `else 3`, `return 3, findings`, or a module-level name bound to 3. A row in the selftest (the script and a sibling `<stem>_selftest.py`) is `== 3`, `!= 3` or 3 passed to a call, whose own statement holds an n/a, not-applicable or skip reason. Fewer rows than sites is a finding. It is parsed, not grepped, because the #1891 review (a0) forged rows from a comment, a docstring and a `[1, 3, 5]` list, and hid sites spelled `else 3` and `SystemExit(3)`. The line-based draft also credited `check_registry_closed` with a neighbouring exit-2 row's "not applicable". A `!= 3` counts only as the test of an `if`. Measured on dev: 6 of 48 scripts had an unproven exit 3, and each now has a row driving its real exit code, with a mutant that turns the site into a pass. Those are `port_fidelity_gate.py` (which had no selftest; it now has one, a guard and a doctor entry), `route_coverage.py`, `check_ts_strict.py`, `check_e2e_paths.py`, `check_toolchain_selftests.py`, and `check_registry_closed.py` (its row's label now says n/a). The gate cannot tell which site a row exercises; each row's mutant proves that. Selftest-only changes to the shipped scripts, so no shipped behaviour changes. Our own design; no framework claim.
