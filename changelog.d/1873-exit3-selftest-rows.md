section: Repository hygiene
- **New doctor gate: every exit 3 a shipped check can give has a selftest row saying why it is not applicable — `scripts/check_exit3_rows.py`** (#1873). `project_gates.py` grades exit 3 as n/a, which never fails a run, so a 3 that means "could not look" passes silently (#1864, #1867, #1872). The gate counts each `checks.json` script's `return 3` / `exit(3)` sites and the selftest rows (the script and a sibling `<stem>_selftest.py`) that assert 3 with an n/a, not-applicable or skip reason; fewer rows than sites is a finding. A labelled row must give its reason on its own line, so a neighbouring row's words do not count (the first draft credited `check_registry_closed` with an exit-2 row's "not applicable"). Measured on dev: 6 of 48 scripts had an unproven exit 3, and each now has a row driving its real exit code, with a mutant that turns the site into a pass. Those are `port_fidelity_gate.py` (which had no selftest; it now has one, a guard and a doctor entry), `route_coverage.py`, `check_ts_strict.py`, `check_e2e_paths.py`, `check_toolchain_selftests.py`, and `check_registry_closed.py` (its row's label now says n/a). The gate cannot tell which site a row exercises; each row's mutant proves that. Selftest-only changes to the shipped scripts, so no shipped behaviour changes. Our own design; no framework claim.
