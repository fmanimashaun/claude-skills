section: rails-flow
- **Every rails-flow hook starts `/bin/bash -p` and sources `hooks/scripts/lib/trusted-env.sh` first — `plugins/rails-flow/hooks/hooks.json`, `plugins/rails-flow/hooks/scripts/lib/trusted-env.sh`** (#1850; P1 of #1843; our own design, the owner's decision recorded on #1850). A repository's checked-in `.claude/settings.json` `env` reached every hook process: 10 hook commands started under a repository-chosen `bash`, `python3` resolved to the repository's, `PYTHONPATH`, `GIT_CONFIG_*` and `BASH_ENV` were honoured (measured on #1843). All 15 rails-flow hook commands now start `/bin/bash -p`, and the lib, sourced as each script's first executable line, unsets `PYTHON*`, `LD_*`, `DYLD_*`, `NODE_OPTIONS`, `NODE_PATH`, `RUBY*`, `PERL5*`, `GEM_*`, `BUNDLE_*`, every `GH_*` except `GH_TOKEN` and `GITHUB_ENTERPRISE_TOKEN` (they point `gh` at another host or repository, or, `GH_PAGER` with `GH_FORCE_TTY`, make it run a program; `GH_TOKEN` stays, because against the real host it only changes identity), `PAGER`, `LESSOPEN`, `BASH_ENV`, `ENV`, `SHELLOPTS`, `BASHOPTS`, `CDPATH`, `GLOBIGNORE` and every `GIT_*` outside an allowlist, sets `PYTHONNOUSERSITE=1` (python's `-s`), unsets `HOME`, `XDG_*`, `SSL_CERT_FILE` and `SSL_CERT_DIR` when relative, unresolvable or at or inside the repository (a `HOME` that IS the repository root, as with a stray `~/.git`, is kept, with `GIT_CONFIG_GLOBAL=/dev/null` so a committed `.gitconfig` is not the user's global config), and rebuilds `PATH` from absolute entries outside the repository (the outermost Gemfile or .git ancestor of the working directory, symlinks resolved). It uses shell builtins only, bounded loops and bash 3.2, the requirements of the #1826 review. `rf_trusted_python` is available for a script that wants an interpreter whose link target is outside the repository too. What it does not close: `disableAllHooks` and a repository's own settings hooks, so the guarantee is still inside a trusted workspace. A system with no `/bin/bash` (NixOS) cannot start a hook, which is a non-blocking error: a gate fails open there. Tested by `python3 plugins/rails-flow/scripts/check_hook_gates.py --only hostile_env`, red on `dev` for every hook before this change. The gates still judge the command's environment, not the hook's: the lib copies every inherited `GIT_*`, `GH_*` and `CDPATH` to `RF_INHERITED_<NAME>` before it unsets them, and `release-gate.sh` (`GH_REPO`) and `command_cwd.py` (the `GIT_*`/`GH_*`/`CDPATH` refusal to follow a `cd`) read the copy; without it the scrub would have blinded them to a `GH_REPO=other/fork` the command inherits.
