section: rails-flow
- **The git shim refuses `git config` of a key that runs a program — `plugins/rails-flow/git-shim/git`, `plugins/rails-flow/scripts/git_shim_selftest.py`, `plugins/rails-flow/scripts/mutations/git_shim.py`** (#2021, the coordinator's scope decision recorded on the issue). `diff.external`, `core.pager`, `core.editor`, `sequence.editor` and `gpg.*program` make git run a program, which finds the real git on its own PATH, never the shim, so it could run a refused command unseen (a0 measured it for `diff.external`). Naming any of them in `git config` is now refused, as `core.hooksPath` already is; a `credential.helper` whose value starts with `!` is refused too, while a named helper (`store`) still runs. A row and a mutant per key, including `core.fsmonitor` and `core.sshCommand`, whose `git config` rule had none. The shim header now states that `git clone --config`/`-c` setting such a key in a NEW clone is out of scope (not the session's repository; the guarantee moves to #1789/#1790). Our own design; no framework claim.
