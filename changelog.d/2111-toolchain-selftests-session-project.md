section: rails-flow
- **`check_toolchain_selftests.py` runs every shipped selftest with the session's project named, so a session without `CLAUDE_SESSION_PROJECT_TOP` no longer fails them on `git add -A` — `plugins/rails-flow/scripts/check_toolchain_selftests.py`, `plugins/rails-flow/scripts/mutations/check_toolchain_selftests.py`** (#2111). The rails-flow git shim lets a selftest stage its own fixture repository only when it knows the session's project, and the SessionStart hook exports that only when it started in a repository; in a session without it, `project_gates` reported `toolchain-selftests` ERR on `docs-layout`, `project-wiki-drift`, `generated-paths-untouched` and `migration-order`, which blocked every Retask `gh pr ready`. The check now sets the variable to the cwd's git toplevel when it is unset or empty, never overriding a value the caller set; the shim is unchanged. Measured from a Retask worktree with the variable unset and the 1.62.1 shim first on PATH: 4 findings before, 0 after (52 selftests).
