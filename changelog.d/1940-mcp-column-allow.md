- **`mcp-personal-fields` can allow a single column, not only a whole category — `plugins/rails-flow/scripts/check_mcp_personal_fields.py`** (#1940, a follow-up to #1931). An allow entry in `.rails-flow/mcp.json` shaped `table.column` admits that column alone, for example `{"allow": {"client_cost_report": ["earnings.amount"]}}`, so a project can return one `work_record` column without admitting every `work_record` column; any other entry is a category, as before. Asked for by the owner on Retask #1724 (relayed by the coordinator). Rows: a column entry admits that column and only that column, a column entry for another tool covers nothing, and a category entry still admits the whole category. 2 new mutants; the real guard run catches all 18. Also (from the #1941 review, a #1935 defect): a malformed `allow` (a non-object, a null or string value, a nested list) is could-not-check (exit 2) instead of a traceback or a string silently read as characters, with a row for each shape and a mutant. Our own design; no framework claim.
