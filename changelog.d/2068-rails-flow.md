- **A pre-warmed `claude bg-spare` process no longer wins the coordinator election, so a real session can be coordinator — `plugins/rails-flow/hooks/session-reset.mjs`** (#2068). Claude Code keeps a spare process ready (`claude bg-spare --bg-spare ...`); it starts with no turns, so the election read it as a new session and it claimed the role, leaving every real session "implementation" (a resumed session never claims) and automatic compact and clear off everywhere. The election script now never lets a process whose command line carries `--bg-spare` claim (it reports `spare`, which parses to no role) and no longer counts a claim held by such a process as live, so the next real start replaces it; `RAILS_FLOW_ROLE=coordinator` still forces a claim. Three selftest rows (the spare never claims, a spare's claim is replaced, a live real coordinator is still not displaced) and two mutants. Known limit: a real session that starts life as a spare, if the engine does not fire `session.start` again, keeps no role until it is started with `RAILS_FLOW_ROLE=coordinator`. Our own design; the owner's rule on one coordinator per machine, 2026-10-09.
