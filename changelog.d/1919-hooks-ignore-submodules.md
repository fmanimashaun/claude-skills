section: rails-flow
- **No shipped hook or script runs a submodule's own clean filter any more, and a lint keeps it that way — `plugins/rails-flow/hooks/scripts/session-start.sh`, `stop-gate.sh`, `guard-claims.sh`, `plugins/rails-flow/hooks/lane-band.js`, `scripts/lint_self_consistency.py`** (#1919, after #1916). Measured on git 2.50.1: `git status` (with `-uall` or `--no-optional-locks` too) and `git diff HEAD` recurse into a submodule. A same-size change then makes git hash a file through a `filter.<name>.clean` named in THAT repository's own config: a command the repository chose, run before the user is asked anything. `diff --cached` and a diff between two refs do not. A grep of every `git status` / `git diff` in `plugins/` found eight that read a user's working tree: the four hooks above, `project_gates.py` (which the `guard-pr-ready` hook also runs), `status_board.py`, `build_project_wiki.py`, `check_spec_review.py` / `dev_baseline.py` (`diff HEAD`, `diff <base>`), and, through `_git(` helpers, `project_gates.py:720`, `route_coverage.py`, `assign_lanes.py` and `classify_door.py` (#1920 review). Each now passes `--ignore-submodules=dirty`; the `where_stopped.py` and `worktree_guard.py` lines from #1916 are carried too. The new `git-status-recurses-submodules` rule refuses a `git status`/`git diff` in shipped hooks, git hooks and plugin scripts without the flag, unless the line says `submodule-safe: <reason>`. `--cached`, ref-to-ref and `base...HEAD` diffs carry that marker. Fixtures: a `check_hook_gates.py` group (`submodule_filter`) runs session-start, stop-gate and guard-claims in a host whose submodule names a marker-writing filter, plus a same-size change; the marker must never appear. lane-band's unit test pins the flag in its argv. Mutants: one per hook, six for the lint rule. `=dirty`, not `=all` (#1920 security review): both stop the filter, but `=all` also hides a moved gitlink, committed or not, so `classify_door` would have missed a submodule bump; `=dirty` still reports it (measured). The lint requires `=dirty` and names `=all` as the bypass. Trade, stated: edits INSIDE a submodule's working tree now read as clean to these hooks and scripts; a moved gitlink does not. Maintainer scripts under `scripts/` run only in this repository and are out of scope. Our own design; no framework claim.
