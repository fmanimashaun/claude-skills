section: qa-flow
- **The release gate no longer refuses a read-only command because it cannot parse `$(( $2 + 14 ))` or a function defined after a `cd` — `plugins/qa-flow/scripts/push_targets.py`, `plugins/qa-flow/scripts/mutations/push_targets.py`** (#1875). On 2026-10-11 a session was refused "cannot tell which commit or repository this command merges or publishes" for `cd <dir> && for p in …; do …; sed -n "$2,$(( $2 + 14 ))p" "$f" | cut -c1-170; done`, which runs `ls`, `git ls-files`, `sed` and `cut` and merges nothing. Two causes, both in the classifier (measured by bisecting the command with `push_targets.py --classify`): (1) the body of `$(( $2 + 14 ))` was read as a subshell, so `$2` became a command word "built by the shell and could be git or gh"; an arithmetic expansion now runs nothing but the substitutions nested in it, which are still read (`echo $(( $(git push origin main) + 1 ))` is `PUSH_MAIN`), and an inside that is not arithmetic-shaped (`$((git push origin main))`, `$(( $g push ))`, two operands side by side) stays a subshell, and a `$name` operand stays refused because bash evaluates a variable's VALUE as an expression, a `[$( )]` subscript included (a known limit now written in the file's header; `$1`, `${2}`, `$#`, numbers and bare names are accepted, which is what the loops in the issue use); (2) a command that defines a function was refused for a `cd` in it even when it ran no git or gh, and the function's state is now checked only when the command has one (`cd /tmp && f() { git push origin main; }; f` is refused as before). Fixtures: the issue's command verbatim, a plain `for` loop over `sed`, a function after a `cd` (each allowed, in the classifier's selftest and through the real hook), and four commands that merge or push that stay refused. Nine mutants, each replayed by hand; five are new and restore the old behaviour. A first attempt decided "does this merge or publish?" by words in the hook and was dropped: it let `git config core.hooksPath …` through (#1768), because many of the classifier's refusals are deliberate and a word list cannot know them. Our own design; no framework claim.
