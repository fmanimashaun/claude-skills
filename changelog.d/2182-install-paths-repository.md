section: Repository hygiene
- **The doc-pointer lint checks shipped text against the install layout — `scripts/lint_self_consistency.py`** (#2182, release blocker for v1.158.0). Under `plugins/`, a `skills/<name>/…` pointer resolves against `plugins/rails-stack/` (where an installed rails-stack has `skills/`), so it is still verified and a typo still fails; a `plugins/rails-stack/skills/…` pointer in shipped text is now a finding ("clone-only path in shipped text"), even when the file exists. Repo docs keep the clone path, resolved from the repo root. New cases and two guard mutations; the #100 mutation's anchor follows the rewritten code. A second rule, `clone-path-in-shipped-file`, scans every file type under `plugins/` (a printed hint, a json, a docstring, a README) for `plugins/rails-stack/skills/`, except an allow-list of clone-aware code, each with its reason (`doctrine_path.py`, `guard-claims.sh`, `pr_template.py`, `check_hook_gates.py`, `worktree_teardown.py`, `session_coordinator.py`).
