- **New project gate `mcp-personal-fields`: no MCP tool result carries a personal category it was not allowed — `plugins/rails-flow/scripts/check_mcp_personal_fields.py`, `plugins/rails-flow/checks.json`** (#1931, gate 3 of #1885). It reads DECLARATIONS, not a run (coordinator's decision on #1931: deterministic, and it needs no app booted). Every class-form tool is judged, named by its `tool_name` or, when it has none, as `mcp` 1.7.0 names it (class name demodulized and underscored, `lib/mcp/tool.rb` `name_value`, verified in the gem). The only class skipped is an abstract base: a parent of a tool with no `tool_name` and no `sources`. Trade, stated: a parent that a server lists DIRECTLY and that declares nothing is skipped too, because a static scan cannot see the served list. A tool built by `MCP::Tool.define`, `define_tool` or `Class.new(MCP::Tool)` is a finding of its own, since it has no class body to declare in. Each tool declares what its result is built from, `sources: %w[table.column …]`. Every column, and every `sum`/`avg`/`min`/`max` of one, is held to `config/privacy_inventory.yml`; `count(…)` carries no row value; `derived(…)` is skipped on the author's word. Four findings: a tool that declares no `sources`, a column the inventory does not list or lists with no category, a source that is not one of those shapes, and a category other than `none` without an allow-list entry for that tool in `.rails-flow/mcp.json` (`{"allow": {"<tool>": ["<category>"]}}`). The convention is the app's, generalised from Retask; verified 2026-10-12 that the `mcp` gem 1.7.0 has `MCP::Tool.output_schema` and nothing naming sources. One definition of "what is an MCP tool class": `check_mcp_annotations.py` now exposes `class_tools()`, and both gates use it (its guard's 38 mutants are still all caught; one was re-anchored). Run against Retask's dev tree it reports four real decisions: `capacity_report` and `client_cost_report` sum `earnings` columns classified `work_record`, and `lookup` declares no `sources`. Not seen: whether `sources` tells the truth about what the code returns, which the app's own spec holds. 28 selftest rows (25 cases and three exit-code rows) and 15 mutants, all caught in a real guard run. Our own design; no framework claim beyond the gem check above.
