Content beyond that threshold is not loaded at session start." The page gives no byte unit, so the unit is inferred and stated: the maintainer's own index measured 157 lines and 25,248 bytes and its last entry was loaded in full, which a 25,000-byte cut would have dropped, so the limit is 25,600 bytes (KiB) and a file between the two readings is reported with both. The script measures lines and bytes, warns at 80% of either (160 lines, 20,480 bytes), reports "over" past either limit with how many lines are not loaded, and treats 200 lines and 25,600 bytes as still loaded whole. An index already over the limit would be red on day one, so `--baseline FILE` fails only on growth past a recorded size (`--record` writes it, nothing else does). It finds the index through `autoMemoryDirectory` (project, then user settings) or the default under `~/.claude/projects/<path with non-alphanumerics as dashes>/memory/`. `--hook-line` prints one line only when the index is near or past the limit and always exits 0; the SessionStart hook calls it, silent otherwise, since that hook re-fires after every compaction.
