Verified by `doctrine-verifier` on 2026-10-21 against turbo-rails v2.0.23 and Turbo v8.0.23 (`docs/evidence/audits/2026-10-21-hotwire-frontend-claims.md`, H22 and H23, verbatim quotes): the signature protects the integrity of a stream name, not access (`Turbo::StreamsChannel#subscribed` never checks `current_user`, anyone holding a valid signed name can subscribe, and the name does not expire), and a broadcast renders its partial with no request, session or cookies. The old line in `turbo.md` ("`turbo_stream_from` signs them for you") read as protection and is corrected. The new `turbo-streams` row of `plugins/rails-stack/checks.json` reads the source for a `turbo_stream_from` with a literal shared name not declared public with a reason in `.rails-flow/public-streams.json`, a stale or unexplained declaration, a custom channel whose own `subscribed` does not OPEN with the guard (`reject unless subscription_allowed?`, or turbo-rails' `if ... && subscription_allowed? ... else reject`; a `super`, an earlier `stream_from` or a comment does not count; a second `subscribed`, a `define_method`, a `=begin` block or a one-line `def subscribed` is refused as ambiguous) (`Turbo::StreamsChannel#subscribed` never does, so a subclass that only defines the method is still open: corrected in review of #2300 and re-verified, H22c and H22e), and a broadcast partial that uses `current_user`, `current_*`, `session`, `cookies` or `Current.`; it prints how many calls, channels and partials it read. Whether a controller authorized the record behind `turbo_stream_from @record` stays a review judgement. A literal name counts as public only when it is the sole stream argument. A broadcast partial is read as one file (helpers and nested renders are not followed), and the reference says so. The check enforces the shape of the guard, not its boolean logic (pinned as a stated limit). Selftest 38 checks, guard 27 mutations.
