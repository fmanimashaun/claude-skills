- **A change that closes an issue brings its QA case, and a fix the spec that fails without it — `plugins/rails-flow/scripts/check_case_in_diff.py`, `plugins/rails-flow/scripts/mutations/check_case_in_diff.py`, `plugins/rails-flow/commands/fix.md`, `plugins/rails-flow/commands/feature.md`, `plugins/rails-flow/reference/case-per-change.md`** (#1858, slice 4 of #1853). Owner rule 2026-10-11: "every fix or gap or bug must have a case to test it and help to prevent regression"; "u can't build something without a way to test it in qa". Downstream, v1.3.1's five fixes shipped with no catalogue cases until a coordinator noticed. In a project with `qa/test-cases.csv`, `/rails-flow:feature` and `/rails-flow:fix` add or update the manual case in the same PR (the issue in its `Source`), a fix also adds the spec that FAILS without it and records red and green under `## Red/green proof`, and the new `check_case_in_diff.py` verifies over the diff `BASE...HEAD` (refs only, fsmonitor and external diff off) that for EVERY issue the PR closes (`--closes-from-body` reads every GitHub closing keyword) a catalogue row the diff adds or changes names it, that a fix's diff has a spec or test file and, with `--body-file`, the Red/green section. A row that already existed and is untouched does not count. Exit 2 is could not check (the gate runner grades 2 ERROR and 3 not applicable), exit 3 only for no catalogue. The PR template carries the new sections and the existing claims guard enforces whatever sections a project's template lists, so the fail-closed hook is unchanged (it reads the target repository, the class #1516 spent several security rounds on). Twenty-three mutants. Review round 1 (c4, a0): the catalogue is compared as whole CSV records between BASE and HEAD (a multi-line quoted field cannot forge a row, a moved row is not a change), a catalogue renamed or deleted by a change that closes an issue is a finding (exit 1) not "no catalogue", a catalogue named with `--catalogue` that exists nowhere is exit 2, a deleted spec is not a spec the change brings, a note or fixture under test/ is not a spec (a source extension is required), and the catalogue's existence and rows are read from the committed trees, never the working tree. Our own design on the owner's decisions recorded on #1853.
