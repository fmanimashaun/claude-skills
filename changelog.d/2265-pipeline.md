section: pipeline
- **The git-guards selftest runs its cases concurrently — `plugins/pipeline/scripts/git_guard_selftest.py`** (#2265). Maintainer tooling, no external claim. Each of the 40 cases builds its own repositories and spends its time waiting on git and bash processes, so the cases now run on a thread pool (`--jobs N`, default up to 8; `--jobs 1` is the old serial run); the shared tallies take a lock and failures print in case order. On a maintainer's Mac at load 7–12 the run went from 180 s (serial, at its 180 s budget, which timed the gate out in a sweep) to 27 s, with the same 127 checks. The budget is unchanged: #2255's per-gate timing shows the gate at 10.0 s on CI. Half of the local cost was the rails-flow git shim on `PATH` (108 s with it, 59 s without, serial); the change does not depend on it. Both guards that run this selftest (`git_guard_pre_commit`, `git_guard_pre_push`) still catch every mutant by its named fixture.
