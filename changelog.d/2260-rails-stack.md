section: rails-stack (skills plugin: rails-8 + hotwire + fidara-design + code-review)
- **rails-stack declares JavaScript's comment syntax, so a security record can cite a Stimulus controller — `plugins/rails-stack/stacks.json`, `plugins/rails-stack/security/syntax-cases.json`** (#2260). `security.code_syntax` gains a row for `.js`, `.mjs` and `.cjs`: the `/* */` block comment, `<!--` and `-->` as line comments (a line starting with either is a comment in a Script and a syntax error in a Module, so never code), and three `refuse_when` patterns that refuse the whole file because a line-by-line reader cannot be sure: any backtick at all (a template literal's body lines look like code, and an even backtick count proves nothing: a nested template, an escaped backtick, a backtick in a string, in a `${}` substitution or in a comment all keep it even, which five adversary files showed), `<!--` after other text (a comment in a Script, code in a Module), and `{/*` (a JSX comment container). `.ts`, `.jsx` and `.tsx` stay undeclared and refused: ECMA-262 does not define them and no verified source says their comments match; a Rails app's Stimulus controllers under importmap are `.js`, so the main use is covered. Citation: ECMA-262, "Draft ECMA-262 / October 16, 2026", 12.4 Comments, 12.5 Hashbang Comments, 12.9.5 Regular Expression Literals, 12.9.6 Template Literal Lexical Components and B.1.1 HTML-like Comments, quoted and matched in `docs/evidence/audits/2026-10-21-js-comment-syntax-2260.md`. Many Stimulus controllers use a backtick, so many are refused: that is the safe direction; cite a file without one. Cases: 25 new syntax cases (the adversary's inputs among them: five template-literal files, three byte-order-mark files, `{/* */}`, `<!--` as a line start and mid-line, a regex with `//`) plus two that keep the JS markers off `.rb` files. The version is assigned at promotion.
