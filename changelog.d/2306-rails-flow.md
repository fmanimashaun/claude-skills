section: rails-flow
- **Temp dirs are ours by name and gone when the run ends, on a signal too — `plugins/rails-flow/scripts/rf_tmp.py`** (#2306). Our-design change, owner rule of 2026-10-22: "temp folder should be monitored and cleared out". Measured 2026-10-22: 64 `tempfile.mkdtemp` calls in 29 files with no cleanup; the system temp dir held 154,397 entries. `rf_tmp.mkdtemp(<tag>)` makes `rf-<tag>-XXXXXX` and removes it at exit, on SIGTERM or SIGHUP, and on Ctrl-C, keeping a script's own SIGTERM handler. It ships as byte-identical copies in rails-flow, qa-flow, pipeline and design-flow, and the `rf-tmp-drift` lint keeps them identical. Every bare call is converted (68, counting four that arrived on dev during the work), and every guard staging a converted file lists `rf_tmp.py` in `needs`. The new `bare-mkdtemp` lint refuses a `tempfile.mkdtemp` whose function never removes it, and a shell `mktemp -d` with no `trap ... rm`. `scripts/maintainer_doctor.py` reports `temp dirs monitored`: the size and count of the system temp dir and the session scratchpads, plus our `rf-` entries over 24 h. `--fix` removes only those, and only when no live process holds one (`lsof +D`).
