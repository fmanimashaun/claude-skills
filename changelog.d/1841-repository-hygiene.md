section: Repository hygiene
- **A bullet added straight to `### Unreleased` is refused, and the finding names the fragment to write — `scripts/changelog_fragments.py`, `scripts/maintainer_doctor.py`, `scripts/mutations/changelog_fragments.py`** (#1841, phase 2 of #1825). Fragments (`changelog.d/<issue>-<slug>.md`) removed the CHANGELOG conflicts for the PRs that used them, but a bullet added the old way was still accepted, so two PRs could still collide. New gate `changelog direct bullets` (`changelog_fragments.py --check-direct`, read from `git diff origin/dev` like the arm-window gate, a SKIP on a maintainer's machine, and a FAILURE when `GITHUB_ACTIONS` is set, when the base cannot be read; compared with `git merge-base HEAD origin/dev`, so a branch cut before a promotion gets no false finding) compares the CHANGELOG's `### Unreleased` bullets with the base's and refuses one the branch adds, in any section including a `### Unreleased` it opens. Three things are not a direct bullet, each with a selftest row: an edit of a bullet the base already has (headlines are COUNTED per section, so a second bullet with an identical headline is a finding; same headline, same section), a late fold under a release block (`--fold --into`), and the fold's own move, a bullet whose fragment the same change deletes. `CLAUDE.md` step 7 says fragments are required, and `changelog.d/README.md` lists the exceptions. 24 new selftest rows (67 in all), 12 mutants, one per path (the detector, the edit, fold and wrong-fragment exemptions, one fragment excusing one bullet, headline counting, the release-block scope, the fragment path in the message, an unreadable base locally and in CI, the merge-base, deleted fragments). Known limits: a bullet whose headline text is edited in the same change reads as an addition (rename the fragment's headline or move the note), and the headline is the first `**…**` span or the first 60 characters, each replayed by hand. Our own design, the coordinator's assignment on #1841.
