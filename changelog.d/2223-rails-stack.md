section: rails-stack (skills plugin: rails-8 + hotwire + fidara-design + code-review)
- **A project that installs rails-stack now gets a Brakeman gate: the `brakeman` row in `plugins/rails-stack/checks.json`, run by `plugins/rails-stack/scripts/check_brakeman.py`** (#2223). Brakeman already catches the Rails security claims the doctrine states (cross-site scripting through unescaped output, the CSRF setting, SQL injection), and a scaffolded project ran it only if its own `config/ci.rb` had the step; nothing in the toolchain asked. The gate finds Brakeman the way the project runs it (`bin/brakeman`, then `bundle exec brakeman` when the Gemfile names it, then `brakeman` on PATH), reads its JSON report, and fails on any warning or error (reviewed and ignored warnings are Brakeman's own mechanism and are not counted). A missing Brakeman, output that is not a JSON report, a crash and a timeout are each a failure to run, never a skip or a pass. The selftest has 13 checks, with a negative fixture (cross-site scripting in a view must fail it), and the guard has 10 mutations. Measured against the Brakeman docs by `doctrine-verifier` on 2026-10-21 (`docs/evidence/audits/2026-10-21-hotwire-frontend-claims.md`).
