- **A work order can record how far a run got, `resume_lanes.py` lists the lanes a cut-off left unfinished, and a Stop hook commits a lane's tracked changes as WIP — `plugins/rails-flow/scripts/check_handoff.py`, `plugins/rails-flow/scripts/resume_lanes.py`, `plugins/rails-flow/scripts/wip_commit.py`, `plugins/rails-flow/commands/handoff.md`** (#1564; our own design, narrowed by the coordinator under the owner's delegation of tooling choices and recorded at https://github.com/fmanimashaun/claude-skills/issues/1564#issuecomment-6101717465: the `PreToolUse[Bash]` WIP commit on `git push`, `gh pr merge` and `gh pr ready` is NOT built, because a `PreToolUse` hook runs before the user is asked, under an environment a repository's settings can set, so it must never execute repository- or environment-controlled code; threat model in `docs/evidence/audits/2026-10-10-hook-environment-1821.md`, measurement in `docs/evidence/audits/2026-10-11-hook-environment-1843.md`). `check_handoff.py` validates an optional `## Progress` section (Status of `not-started`, `in-progress`, `stopped` or `done`; Last green, which must be `none` or a commit here; Current step; Next step; Pending gates, which a `done` order must say `none` for) with 11 selftest rows; orders written before this still validate. `resume_lanes.py` is read-only, runs no hook and fetches nothing: it lists every order that is not `done` (or records no Progress), whether its branch exists locally or as `origin/<branch>`, which worktree has it and what Progress recorded, exits 1 when a lane is unfinished, and has a 15-check selftest and 8 mutations. `wip_commit.py` (the Stop hook's core) commits TRACKED changes on a `feature/*` or `fix/*` branch only, finds `git` through `test_preflight.trusted_which` (absolute `PATH` entries outside the repository), runs it in a scrubbed environment (no `GIT_*`, a one-directory `PATH`) with `core.hooksPath=/dev/null` and `core.fsmonitor=false`, skips a repository whose OWN config (`.git/config`) names a program for git to run (a `filter.<name>.clean`, `diff.<name>.textconv`, `core.sshCommand`, `core.editor`, a credential helper, an `include`), because `-c` cannot switch off a key whose name the repository chooses (found by the commit security review), never stages untracked files, skips a merge, rebase or cherry-pick in progress, amends only its own unpushed `WIP(auto):` commit, invents no identity and never pushes; its selftest drives hostile environments (a `GIT_CONFIG_COUNT` clean filter, a relative or in-repository `PATH` entry, a repository-local hook, `core.hooksPath` and every program-running key above set in the repository's own config) and each of its 13 mutations is caught by the fixture it names (applied by hand on a copy, not run through the harness). A filter driver or hook the user configured in their own global or system git config still runs, as it does for any git command they run.
