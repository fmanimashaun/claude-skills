section: rails-flow
- **The flows name roles, never a Rails agent — `plugins/rails-flow/reference/stack-roles.md`** (#2173, step 3a of #2183). `/feature`, `/fix`, `/review`, `/issues`, `/handoff` and `/pr-comments` (and `/retro`, `/setup-flow` and the neutral agents that mention them) now ask for the `developer`, `migrations`, `test_runner`, `reviewer`, `security` or `design_auditor` role, resolved by `detect_stack.py --descriptor`. When the project's stack names no agent for a role (a stack whose plugin ships no agents yet, an add-on stack such as Supabase alone, no stack detected), or two stack plugins conflict, the flow stops and asks: it never falls back to a Rails agent (owner ruling on #2180). The six Rails agents moved to rails-stack; `plugins/rails-flow/agents/` keeps a redirect stub for each, for two releases, so a project that updated rails-flow first is told where the agent went instead of finding it missing.
