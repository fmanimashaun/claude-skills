- **The toolchain audit names what the detected stack still needs installed — `plugins/rails-flow/scripts/stack_toolchain.py`** (#2168). Our-design change; the platform facts behind it were verified on 2026-10-21. Each stack declares its plugins and CLIs in a new per-stack `toolchain` descriptor key, which `plugins/rails-flow/scripts/detect_stack.py` validates (a plugin id is `name@marketplace`, no empty install line, a CLI is a bare command name, a `ready` check carries a hint) and reports per matched stack. The script names no stack. It reports each missing plugin with its install line and each missing CLI with the vendor's install command, plus a CLI whose `ready` check fails (Docker's daemon). A CLI that is present is reported with its `--version`, and a project-local one in `node_modules/.bin/` counts as present but is never executed: a diagnostic does not run what the repository ships. The project's own paths are checked before PATH, every hit is resolved and judged by where it really lives (so the project's `node_modules/.bin` reached through PATH, as direnv or `npm run` arrange, is still not run), relative PATH entries such as `.` are skipped, a `ready` probe naming another binary gets the same treatment, and a project path resolving outside the project (a symlink) is not the CLI. Containment is judged by file identity (device and inode), not spelling, so another letter case on a case-insensitive volume or the `/System/Volumes/Data` alias cannot disguise the project; a CLI on PATH runs with the project's directories removed from its PATH (so a `#!/usr/bin/env node` script cannot pick up the project's `node`) and from a neutral working directory, with an allowlisted environment (no `BASH_ENV`, `NODE_OPTIONS`, `RUBYOPT` or `PYTHONPATH`, which direnv or a repository's settings could set from the project). A plugin counts as present when it is enabled: the documented record is `enabledPlugins` in the user, project and local settings files, the most specific scope winning ("Project local sits above shared project", "shared project sits above user", code.claude.com/docs/en/settings). `installed_plugins.json` is undocumented and not read. It is advisory: exit 1 lists what to install, and exit 2 (cannot judge) is never folded into 0. `/rails-flow:toolchain-check` and `/rails-flow:setup-flow` run it. Login state of the Vercel and Supabase CLIs is not claimed yet (#2287); the Playwright image tag (#2285) and Storybook (#2286) are split out. Also: the `check_stack_markers` guard had been inert since #2210, because its staged tempdir lacked the security files `stacks.json` names; it now stages them.
