section: Repository hygiene
- **`scripts/linux_check.sh` installs the host tools a selftest probes and asserts them present before any guard runs — `scripts/linux_check.sh`, `scripts/linux_check_selftest.py`, `scripts/mutations/linux_check.py`** (#1964, from the v1.156.0 release run 38297902322). The container held python3, git and bash only, so `scripts/linux_check.sh test_preflight` reported GREEN while the runner, which has `/usr/bin/pg_isready`, failed the same guard as INERT; a Linux check that cannot see a tool the runner has cannot fail on that class of defect. The container now installs `postgresql-client`, `lsof` and `procps` (`HOST_PACKAGES`, the tools `test_preflight.py` resolves with `trusted_which`) and runs a canary, `linux_check.sh --check-tools pg_isready lsof ps`, which exits 3 naming every missing tool and exits 2 on no names (zero tools checked is not a pass). The canary runs without docker, so its refusal is a selftest row, not a claim. Measured: with the pre-fix `test_preflight.py` from release dev 59ec631e swapped in, the new `linux_check.sh test_preflight` fails with the runner's exact `INERT ... no pg_isready on PATH fails open: silent`; with the fixed file `linux_check.sh test_preflight wip_commit linux_check` passes. Six new mutants (the package dropped, `pg_isready` dropped from the canary, the canary not run, its failure ignored, a missing tool exiting 0, no names passing), each caught by its intended row; 21 mutants in all. node, ruby and zsh are deliberately not installed: a guard that needs them is proven by CI, as the script's header says. Our own design; no framework claim.
