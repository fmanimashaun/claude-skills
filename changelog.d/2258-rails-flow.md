section: rails-flow
- **A claim-carrying body is judged where gh really runs — `plugins/rails-flow/git-shim/gh`** (#2258).
  - **The gap.** `guard-claims.sh` reads the command's TEXT. Over 36 hours, 2821 of 3211 real `gh pr create/edit` and `gh issue comment` calls with a body (88%) put a heredoc, a VAR or a `cd` chain before `gh`. For those the hook could not tell the directory, so the PR template went unchecked. An inline `--body` or a `--body-file "$F"` was not read at all. `create` and `edit` behaved the same; the command's shape decided.
  - **The fix.** The gh shim, the layer that already guards `gh pr ready` (#1839), now judges the body with the argv the shell expanded, in the directory gh runs in: inline `--body`/`-b`, `--body-file`/`-F`, short forms joined to their value, and an alias that expands to `pr create`. It copies the body to a temp file it controls and hands it to `guard-claims.sh` in its plainest shape, so no rule is restated. `plugins/rails-flow/hooks/scripts/guard-claims.sh` runs in a new STRICT mode there (`RAILS_FLOW_CLAIMS_STRICT=1`), where a body it cannot read is a refusal.
  - **What gh posts is what was judged.** gh is handed the judged copy (`--body-file <temp>`) in place of the body flags, and a trap removes the copy after gh runs.
  - **NOT checked, said on stderr.** A body from stdin, `/dev/stdin`, `/dev/fd/N`, a fifo or any non-regular file: only gh may read it, and a fifo with no writer would hang. Another repository's template (`-R`, or `GH_REPO`). A body gh composes itself: `--fill`, `--fill-first`, `--fill-verbose`, `--template`, `--editor`, `--web`, or none given. Out of scope: `gh pr comment`, `gh issue create`, and a `gh api` call carrying a body. The PreToolUse hook stays the early tripwire, with its fail-open unchanged.
  - **Proof.** `gh_shim_selftest.py` "claim bodies" runs each shape with a refused and an allowed body. `check_hook_gates.py` has 8 new fixtures, for each shape and for strict mode.
