section: Repository hygiene
- **A report of what third-party SessionStart hooks add to every session and compaction — `scripts/report_third_party_hooks.py`** (#1887, slice 5 of #1683). `check_hook_output_budget.py` ratchets the hooks we ship; the ones other plugins install are paid the same way, but we do not ship them, so this is a maintainer report, not a gate. It runs each SessionStart command of every enabled non-claude-skills plugin's newest numbered install (a commit-hash cache directory never counts as a version) in the ratchet's own fixture project, once per source its matcher selects (by the hooks docs' rule: exact names split on `|`/`,`, otherwise an unanchored regex; sources startup, resume, clear, compact, fork), and reports stdout bytes per event with a token estimate; a failing or hung hook is reported with its status, never as 0 bytes, and a timeout kills the hook's whole process group. On 2026-10-12 here: 5,602 B (~1.4k tok) on startup, clear and compact — superpowers 3,616, explanatory-output-style 1,303, remember 550, security-guidance 133 — and about 1,985 B on resume and fork, where superpowers' `startup|clear|compact` matcher does not fire. Figures are stdout bytes, which include a hook's JSON wrapper, so they over-estimate the injected text; a settings key whose parts are not plain names is skipped, so nothing outside the plugin cache is run. It cannot see state outside the project (`remember` prints the user's memories), so the figures are a floor: the ~5.7k-token `remember` figure #1683 cited came from a real session. Its selftest is a doctor gate; mutation guard `scripts/mutations/report_third_party_hooks.py` (9 mutants). Our own design: coordinator-approved split of #1683.
