- **`/rails-flow:claim-coordinator` takes the coordinator role for the session that runs it, with no trip to the session that holds it — `plugins/rails-flow/scripts/claim_coordinator.mjs`** (#2070). Until now a session elected the wrong role could only be fixed by restarting it with `RAILS_FLOW_ROLE=coordinator` or by going to the other session. The command passes the Bash tool's `$PPID` (the Claude Code process: measured, the tool's shell is its child) and `$CLAUDE_CODE_SESSION_ID` to the election script's force path, which writes the claim for that pid. Every session now re-reads the claim at each turn start (`syncRole` in `plugins/rails-flow/hooks/session-reset.mjs`), so the claimer becomes coordinator and the previous holder becomes implementation at their next turn, no restart; a `RAILS_FLOW_ROLE` override is never rewritten. Run it only when the owner says this session coordinates. Five selftest rows and four mutants. Not measured live: that the engine's `$.session.id()` equals `$CLAUDE_CODE_SESSION_ID` — the sync compares pids, not ids, so the claim holds either way. Our own design; the owner's request, 2026-10-14.
