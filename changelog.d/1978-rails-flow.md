- **guard-worktree.sh's line scan is linear, so a large command with no python3 is refused in time — `plugins/rails-flow/hooks/scripts/guard-worktree.sh`, `plugins/rails-flow/scripts/check_hook_gates.py`, `scripts/mutations/hook_guard_worktree_failopen.py`** (#1978). The scope loop sliced the text with `${rest#*$'\n'}` and `${rest%%$'\n'*}`, which bash 3.2 does in quadratic time: on one 150 KB line they took 16 s and 4 s, so with python3 missing a 150 KB `git worktree add` ran past the hook's 15 s timeout (11.8 to 20.5 s measured), and a killed hook lets the command run. The loop now reads lines from a here-string (`while IFS= read -r line … done <<< "$seg"`), so the same payload is refused in 0.22 s. Nothing extra is refused: there is no size cap, and an ordinary large command is still allowed. Two timed rows in the `guard_worktree_failopen` group run the gate with python3 missing at 150 KB: a worktree add is refused, and an `echo` is allowed, each in under 5 s. A mutant restoring the slicing loop is caught on macOS and in `scripts/linux_check.sh`. Our own design; the coordinator's assignment on #1978.
