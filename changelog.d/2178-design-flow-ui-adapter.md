section: design-flow
- **BREAKING for any caller by name: the Rails rendering half moves into a UI adapter inside design-flow, `plugins/design-flow/ui/viewcomponent-erb/`, and its two agents are renamed — `design-flow:design-porter` becomes `design-flow:rails-ui-porter`, `design-flow:ui-composer` becomes `design-flow:rails-ui-composer`** (#2178). Nothing moves to rails-stack; design stays neutral and a stack descriptor selects the adapter with `ui.implementation`, used as the directory name so there is no table to drift. The twelve checks and gates that read `.erb` and `app/components` (`check_surface_layout`, `check_table_layout`, `check_modal_fit`, `check_layout_composition`, `check_component_contract`, `variant_conformance`, `check_token_drift`, `setup_doctrine_crosscheck`, `canvas_manifest`, `port_fidelity_gate`, `source_text`, `content_floors`) move to `plugins/design-flow/ui/viewcomponent-erb/scripts/`, their guards beside them, and `plugins/design-flow/checks.json` runs them from there; the adapter is described by `plugins/design-flow/ui/viewcomponent-erb/adapter.json`. A project that named either agent in a command, a hook, a script or a descriptor must use the new name. This is our own architecture decision, not a framework claim, so there is no doctrine-verifier step.
