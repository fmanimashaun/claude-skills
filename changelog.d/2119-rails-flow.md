- **`security-auditor` is mandatory per threat-model row, and `gh pr ready` needs its current record — `plugins/rails-flow/scripts/check_security_review.py`** (#2119). Our-design change, no external claim. When a change adds or edits `docs/security/threat-models/<slug>.md`, the sweep (`checks.json`, id `security-review`) requires `docs/evidence/reviews/prs/<slug>/security-audit.md`: `Head: <sha>` for the current HEAD, one line per `mitigate` and `accept` row (`TM-n: implemented <file:line>` with the file committed at HEAD (read from git, no absolute or `..` path, never a symlink) and the line being code, not blank, a comment, inside `=begin`/`=end` or a `/* */` span, or a heredoc body (several on one line included), `holds`, `stale`, `not implemented`) and a `VERDICT`. A missing, stale or incomplete record is exit 1, a `mitigate` row not implemented or an `accept` row gone stale is exit 1, marked BLOCKING, for a human (never exit 3, which the project gates read as not applicable, #1873), and a red sweep means `guard-pr-ready.sh` refuses `gh pr ready`. The `security-auditor` agent and `/rails-flow:feature` carry the record's shape. Stack-neutral (EPIC #2162): `plugins/rails-flow/scripts/check_security_review.py` keeps only the neutral rules for what is not code (blank, `#`/`//`, `/* */`) and takes each stack's block comments and heredocs from its descriptor's `security.code_syntax` by file extension; its selftest uses a made-up syntax and runs every stack's own `syntax_cases`. **Review:** `detect_stack.py` refuses a `code_syntax` heredoc with no `(?P<id>...)` group (check_security_review read the terminator from it and crashed) and requires each block comment to say `column0` (true or false); a `column0` opener (Ruby's `=begin`) counts only at the start of the raw line, so an indented one no longer hides code. **Adversary pass:** a column-0 block closes only at the start of a line; any other block opens after code on the same line too; a bare heredoc ends only at its exact terminator, a `~`/`-` one after stripping, lowercase ids included; a new `security.data_markers` key ends code at a marker line; a cited path must be a regular file (mode 100644/100755); a row answered twice is refused; a cited file type no detected stack declares in `code_syntax` is refused, never read with neutral rules. Limits stated: multi-line string literals, dead code, a byte-order mark. Every opener and closer on a line is walked, so a line that closes one span and opens another, or reopens one on its closing line, leaves the next line non-code.
