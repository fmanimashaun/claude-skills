- **New project gate `mcp-end-to-end`: an app with an MCP server names the spec that drives it end to end — `plugins/rails-flow/scripts/check_mcp_end_to_end.py`, `plugins/rails-flow/checks.json`** (#1930, gate 4 of #1885). It applies when the Gemfile declares the `mcp` gem. The project then names its request-level spec in `.rails-flow/mcp.json` (`{"end_to_end_spec": "…"}`). The gate holds it to three things: the file exists; it is a request, system or integration spec (by path or `type: :request`); and it reaches both `tools/list` and `tools/call`, literally or through a `spec/support` helper whose body sends them. doctrine-verifier CONFIRMED the method names: MCP specification 2025-06-18 and 2026-07-28; `mcp` gem 1.7.0 `lib/mcp/methods.rb` `TOOLS_LIST`/`TOOLS_CALL`. The gem with no declaration is a finding, because nobody deciding is not "nothing to check"; no gem is n/a. Not seen: whether the spec passes (the suite's job), or a helper reached through another helper. 14 selftest rows and 8 mutants.
