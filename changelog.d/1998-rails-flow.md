section: rails-flow
- **`wip_commit.py --selftest` runs under rails-flow's git shim, and its no-identity row no longer depends on the machine — `plugins/rails-flow/scripts/wip_commit.py`, `plugins/rails-flow/scripts/mutations/wip_commit.py`** (#1998). Run from the Claude Code Bash tool the shim is first on PATH, so the selftest's `shutil.which("git")` was the shim, which refused the fixture's own `-c protocol.file.allow=always submodule add` into a temp repository; the selftest failed at its submodule row and the shim's allowlist was not widened for it. The selftest now finds the real git past any `git-shim` directory (`real_git_outside_shims`, a function with a row and two mutants). That exposed a latent defect the shim had been masking: the row "with no git identity configured it commits nothing and invents none" passed only on a Mac because the shim refused the commit first; git itself auto-detects an identity from the account and host name on macOS and committed. The fixture repository now sets `user.useConfigOnly`, so "no identity configured" means the same everywhere. `wip_commit.py` itself is still refused by hand from the Bash tool (it commits with hooks off, #1994); its Stop-hook path is unaffected. Our own design; the coordinator's assignment on #1998.
