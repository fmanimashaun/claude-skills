- **`check_mcp_annotations.py` can pass a registry-driven MCP server — `plugins/rails-flow/scripts/check_mcp_annotations.py`** (#1988, found fixing Retask-platform#1741). A server built as `MCP::Server.new(tools: policy.tools)` (a registry filtered by role) could never pass: the scan accepts `tools:` only as a literal `[...]`, reported "could not check" (exit 2, never a pass), and the app had no honest way to say more (`tools: [*policy.tools]` would satisfy the test while the scan read nothing inside it). Now the call can carry `# mcp-tools: registry Mcp::Tools::ALL` on the line above it or trailing it, and the scan checks the registry itself: it must be defined once as a literal list of constants (a splat, a call, an empty list or two definitions stay could-not-check), every entry must be a tool class the scan found and judged, and a concrete tool class missing from the list is a finding. Decision kind: our own design, with no upstream; the choice (option 2 of the issue's proposal, made verifiable by reading the registry, in the direction the coordinator named: an explicit, verifiable declaration, never accepting any `[...]`) is recorded in a comment on #1988. Limit, stated in the script: the declaration is a checked claim about the registry, not proof that the server's `tools:` is drawn from it. 11 new selftest cases (76 in all) and 8 new mutants (46 in all, all caught).
