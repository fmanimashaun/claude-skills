- **`check_mcp_annotations.py` can pass a registry-driven MCP server — `plugins/rails-flow/scripts/check_mcp_annotations.py`** (#1988, found fixing Retask-platform#1741). A server built as `MCP::Server.new(tools: policy.tools)` (a registry filtered by role) could never pass: the scan accepts `tools:` only as a literal `[...]`, reported "could not check" (exit 2, never a pass), and the app had no honest way to say more (`tools: [*policy.tools]` would satisfy the test while the scan read nothing inside it). Now the call can carry `# mcp-tools: registry Mcp::Tools::ALL` as a comment on the line above it or trailing it (the same words in a string declare nothing), and the scan checks the registry itself: it is found by its full path (`Mcp::Tools::ALL` is not another module's `ALL`) and must be defined once as exactly a literal list of constants (a splat, a call, an empty list, two definitions, a computed definition, anything after the `]` but `.freeze`, or a `<<`, push, concat or `+=` on it anywhere stay could-not-check), every entry must be a tool class the scan found and judged, and a concrete tool class missing from the list is a finding. Decision kind: our own design, with no upstream; the choice (option 2 of the issue's proposal, made verifiable by reading the registry, in the direction the coordinator named: an explicit, verifiable declaration, never accepting any `[...]`) is recorded in a comment on #1988. Limit, stated in the script: the declaration is a checked claim about the registry, not proof that the server's `tools:` is drawn from it. Review by dd of the first head found four false passes (the wrong constant, an unread tail, a grown list, a mark in a string), each now a selftest row and a mutant. 24 new selftest cases (89 in all) and 16 new mutants (54 in all, all caught).
