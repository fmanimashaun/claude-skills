- **The test-preflight hook takes its interpreter from the lib, and the four `hook_test_preflight` survivors were equivalent mutants, not missing fixtures — `plugins/rails-flow/hooks/scripts/test-preflight.sh`, `scripts/mutations/hook_test_preflight.py`, `plugins/rails-flow/scripts/check_hook_gates.py`** (#1893). The v1.156.0 sweep reported four survivors in the guard of the hook's interpreter lookup ("a python3 inside the repository is run", "PATH entries are globbed", "a relative PATH entry is searched", "python3 is not run isolated"). Once `lib/trusted-env.sh` (#1850) rebuilds PATH first, the hook's own copy of those rules could never fire: PATH already holds only absolute entries outside the repository, globbed or relative entries are gone, and PYTHON* is unset, so no fixture could tell a mutant from the original. The lookup is now `rf_trusted_python` (the same rules, plus the check that the interpreter's own link target is outside the repository), proven by the `hook_trusted_env` guard and the hostile-environment group; the 73 fixtures of the `test_preflight` group pass unchanged against the real hook. What the hook still adds is `-I`, which no longer had a fixture (PYTHONPATH is scrubbed before it could matter): a new fixture runs an interpreter outside the repository that records the first word it is given, and a mutant drops the flag. The guard keeps its four unrelated mutants (missing script, default expansion, the stderr redirect, the exit status; the redirect's mutant now expects the fixture that actually reaches it, a script python cannot open, because a missing python3 no longer reaches the redirect) and gains the `-I` mutant and one that restores the shell's own lookup (killed by the symlink-into-the-repository fixture). Verified: `--only test_preflight` 74 checks; `mutation_check.py --guard hook_test_preflight --jobs 1` all 6 caught; the two new mutants replayed by hand. Our own design.
