- **A PR that closes an issue updates the registry rows that point at it — `plugins/rails-flow/scripts/check_registry_closed.py`, `plugins/rails-flow/scripts/mutations/check_registry_closed.py`, `plugins/rails-flow/checks.json`, `plugins/rails-flow/commands/feature.md`, `plugins/rails-flow/commands/fix.md`** (#1857, slice 3 of #1853). Downstream (Retask, #1853) the requirement registry was last edited the day the audit issue closed, so 117 rows still said partial, missing or deviates and pointed at the closed audit issue, and the status report showed fixed gaps as open. A registry row (`issue` a JSON number) whose issue is closed, on GitHub or named by `--closes` or `--closes-from-body` (every GitHub closing keyword in any case: `Closes #12`, `fixes #12`, `Resolved #12`, and for this repository, told from its `origin` remote, `owner/repo#12` and a full issue URL; another repository's references close nothing), must be `status: "done"` with `closed: true`, else it is stale; an issue closed as not planned or as a duplicate was never fixed, so its rows must say `owner-decision` or `deviates`, never `done`; a row saying `closed: true` while its issue is open is a finding too. One bounded `gh issue view` per distinct issue (at most 200); a key repeated within an entry is refused (the last would hide the first; both the qa-flow and the rails-flow reader refuse it); could not check (a missing or failing `gh`, GitHub unreadable, more than 200 issues, a broken registry) is exit 2, which the gate runner grades ERROR, never exit 3, which it grades not applicable and never fails; exit 3 is only "no registry". `/rails-flow:fix` and `/rails-flow:feature` run it before merging and refuse to call a PR done while a row is stale; it ships as a `checks.json` entry. The check has its own small reader of the registry grammar because plugins install alone (the maintainer gate `registry reader parity` keeps it answering like qa-flow'"'"'s). Forty mutants, each caught by the row that names it. Our own design on the owner'"'"'s decision recorded on #1853; no framework claim.
