- **A PR that closes an issue updates the registry rows that point at it — `plugins/rails-flow/scripts/check_registry_closed.py`, `plugins/rails-flow/scripts/mutations/check_registry_closed.py`, `plugins/rails-flow/checks.json`, `plugins/rails-flow/commands/feature.md`, `plugins/rails-flow/commands/fix.md`** (#1857, slice 3 of #1853). Downstream (Retask, #1853) the requirement registry was last edited the day the audit issue closed, so 117 rows still said partial, missing or deviates and pointed at the closed audit issue, and the status report showed fixed gaps as open. A registry row (`issue` a JSON number) whose issue is closed, on GitHub or named by `--closes` (the PR'"'"'s `Fixes` lines), must be `status: "done"` with `closed: true`, else it is stale; a row saying `closed: true` while its issue is open is a finding too. One bounded `gh issue view` per distinct issue (at most 200); a missing or failing `gh`, no registry, or too many issues is exit 3 (could not check), never a pass. `/rails-flow:fix` and `/rails-flow:feature` run it before merging and refuse to call a PR done while a row is stale; it ships as a `checks.json` entry. The check has its own small reader of the registry grammar because plugins install alone (the maintainer gate `registry reader parity` keeps it answering like qa-flow'"'"'s). Seventeen mutants, each caught by the row that names it. Our own design on the owner'"'"'s decision recorded on #1853; no framework claim.
