section: Repository hygiene
- **The Linux check installs zsh and asserts it, and `git_shim_selftest.py` says when its zsh row did not run — `scripts/linux_check.sh`, `scripts/linux_check_selftest.py`, `scripts/mutations/linux_check.py`, `plugins/rails-flow/scripts/git_shim_selftest.py`, `plugins/rails-flow/scripts/mutations/git_shim_selftest_skip.py`** (#1971, the host-tools audit after #1964). I ran every selftest that reaches a `node`, `ruby`, `perl`, `zsh`, `shasum` or `gh` lookup in the container and on macOS. One read green when it should not: `git_shim_selftest.py` passed 313 checks in the container against 314 on macOS, because its zsh row ran only `if shutil.which("zsh")` and the container had none. zsh joins `HOST_PACKAGES` and `CANARY_TOOLS`, so the container runs the row (314). Where zsh is absent anyway, the row prints that it did NOT run and is not counted: the row is now `zsh_row()` with an injectable `which`, and a new case ("zsh absent: the zsh row says it did NOT run, and counts nothing") asserts the skip text and that the skipped row counts nothing. A new guard, `plugins/rails-flow/scripts/mutations/git_shim_selftest_skip.py`, catches the skip line being dropped and the skipped row counting as a pass (9f's review of #1972). Two mutants (zsh not installed, the canary not asking for it) are caught. Every other lookup fails loudly, prints an explicit skip, or reads the same in both places (the table is on the PR). Our own design: the coordinator's assignment on #1971.
