section: rails-flow
- **The six fail-closed PreToolUse gates carry `"onFailure": "block"` — `plugins/rails-flow/hooks/hooks.json`** (#1939, from the upstream review on #1938). A gate denies by exiting 2, but only while it runs: a gate whose script or `bash` was missing, that crashed with another status, or that timed out was a non-blocking error to Claude Code, and the action went through. Claude Code 2.1.295 added `onFailure` on a command hook (`"continue"` by default, or `"block"`, which does what exit 2 does on that event); `guard-bash.sh`, `guard-claims.sh`, `guard-worktree.sh`, `guard-pr-ready.sh`, `guard-lane.sh` and `guard-migrate.sh` now set it. doctrine-verifier CONFIRMED the field, its values, its effect and the boundary (code.claude.com/docs/en/hooks.md: "Requires Claude Code v2.1.295 or later"); the docs are silent on plugin files and older versions, so those are MEASURED, on this machine: `claude plugin validate` on 2.1.296 accepts the field in a plugin's `hooks/hooks.json` and rejects an invalid value; a real `claude -p --plugin-dir` run on 2.1.296 with a missing gate script refused a Bash call with the field and ran it without; on 2.1.292 the same plugin passed `validate` and the call ran (the field is ignored, so older Claude Code keeps today's behaviour). Exit 0 still allows, exit 2 still denies; the gates' own statuses are 0 and 2 only. **Cost, stated:** each gate's `timeout` (10 or 15 s) is now a hard deny threshold, so a gate starved by a heavily loaded machine refuses the command instead of letting it through (`check_hook_gates.py` already reports a starved gate at load 22). Our own design, recorded on #1939; the framework claim is the verified one.
