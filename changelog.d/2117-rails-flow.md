- **`/rails-flow:secure-design`: a threat model before the criteria, only when the plan names a security boundary — `plugins/rails-flow/commands/secure-design.md`** (#2117). Our-design change, no external claim. `security_scope.py` scans the plan and planned paths (exit 1 a boundary, 2 could not classify), `check_threat_model.py` checks `docs/security/threat-models/<slug>.md` is complete (every STRIDE row has a unique `TM-n` ID and a decision, every `accept` reasoned), `/rails-flow:feature` and `/rails-flow:spec` call it, and both scripts carry a selftest and a mutation guard. `security-auditor` before `gh pr ready` (#2119) and `[security]` criteria (#2118) follow. **Stack-neutral (EPIC #2162):** the process is the same for every stack, and each stack's security surface comes from its descriptor: `plugins/rails-flow/scripts/detect_stack.py` gains a per-stack `security` key (checklist, scanners, cases, boundary_text, boundary_paths), validated and reported per matched stack; `security_scope.py` keeps only plain-language signals and adds the detected stacks' spellings and paths, and its selftest runs every discovered stack's own cases. `detect_stack.py` scans sibling plugins only in a checkout or the installed cache: a copy staged under the system temp directory walked every tempdir (one selftest took over ten minutes; now 0.14 s).
