section: pipeline
- **`/pipeline:deploy-cloud` is the stack-neutral lifecycle; the stack declares the deploy agent — `plugins/pipeline/commands/deploy-cloud.md`, `plugins/pipeline/scripts/deploy_target.py`** (#2179). The command used to be the Kamal-on-Rails deploy: it named Kamal, `.kamal/deploy.env` and Rails credentials, and delegated to one hard-coded agent. It now gates (certification, a release artifact), asks `deploy_target.py` which agent the project's stack descriptor declares (`deploy.agent`), opens the attempt ledger, and delegates to that agent by name, handing it `BREAKER`, `SECRET_SCAN`, `APM_ADVISORY` and `STOP_CONDITIONS` as absolute paths (a plugin cannot reach another's files by relative path). Exit `1` (no stack, or a stack that declares no deploy) and exit `2` (cannot judge: a broken manifest, two stacks that both declare a deploy target, an agent that does not exist) STOP with the reason and never fall back to a target; the selftest has a fixture for each. `detect_stack.py` ships here as a byte-identical mirror of rails-flow's, held by the `detect-stack-drift` lint rule, because a plugin installs alone. An architecture change and the maintainer's own decision (#2162): no framework claim, so no doctrine-verifier step. The Vercel deploy agent (#2167) is a new descriptor in its own plugin and needs no change here. The agent and `kamal_destination.py` left for `rails-stack`. The version is assigned at promotion.
