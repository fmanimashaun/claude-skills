section: Repository hygiene
- **`changelog_fragments.py --fold` matches a fragment's section by its name or its whole heading, never by prefix — `scripts/changelog_fragments.py`, `changelog.d/README.md`** (#2099). A fragment's `section:` used to be a PREFIX of a `## ` heading, so #2035's `section: rails-stack (rails-8 + hotwire ...` matched an old 2026-09 rails-stack heading that still held a stale `### Unreleased` and the arm of v1.157.4 filed the bullet there; it was moved by hand. Now `section:` is the heading's name (its text before the first ` (`: `rails-flow`, `Repository hygiene`) or the whole heading; a prefix of a title matches nothing and the error names the headings that start with the same word; two different headings with one name (`rails-stack` has two) are an error naming both, and a `### Unreleased` never breaks the tie (`--into` still chooses by the armed release block). The two `rails-stack` fragments already in `changelog.d/` now carry the whole heading. The selftest gains rows for two sections sharing a prefix with a stale `### Unreleased`, and the mutation guard gains two mutants (prefix matching restored; `### Unreleased` breaking a tie again). Maintainer decision: the issue's own fix, "match the section heading exactly (or by an explicit key), refuse an ambiguous match by name".
