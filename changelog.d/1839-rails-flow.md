- **`gh pr ready` is gated where argv is final: a `gh` shim beside the git shim refuses it unless the sweep record for HEAD is green with zero skips — `plugins/rails-flow/git-shim/gh`, `plugins/rails-flow/hooks/scripts/lib/pr_ready_guard.py`, `plugins/rails-flow/scripts/gh_shim_selftest.py`** (#1839, the guarantee behind #1565's tripwire; the owner's ruling on #1793). `guard-pr-ready.sh` reads the shell TEXT of a Bash command and three shell-adversary rounds on #1831 kept finding spellings text cannot settle, so it was reclassified a tripwire. The SessionStart hook already puts `git-shim/` first on the Bash tool's PATH; a `gh` there receives the arguments AFTER the shell has expanded them. It runs `pr_ready_guard.py --shim` (the same record and rules as the hook, one `judge_record`): in force only where project_gates runs; `--undo` passes, but only after every other argument has been judged; a repository named by `-R`/`--repo` (also between `pr` and `ready`), a URL or `GH_REPO` is refused; every other word must be a plain PR number or branch; a gh alias that expands to `pr ready` is judged; a missing python3 refuses a `pr ready` (and only that: `gh pr view` still runs). `RAILS_FLOW_GH_OK=1` is the audited escape, as for the git shim. The six spellings the hook documents as limits (`x=ready; gh pr $x 5`, `/usr/bin/env gh pr ready 5`, `gh pr rea{d,}y 5`, `echo 'gh pr ready 5' | sh`, `bash <<< 'gh pr ready 5'`, `git -c alias.x='!gh pr ready 5' x`) are run through a real shell in `gh_shim_selftest.py`: the hook alone lets each through (its documented limit, kept as it is) and the shim refuses each, with a stub gh that records whether it ran. 44 checks; 13 mutants across the new guards `gh_shim` and `gh_shim_judge`, each replayed by hand and dying on its named case. Limits, stated in the shim: an absolute `/usr/bin/gh`, `command gh`, `env -i gh`, a session where the SessionStart hook did not run, and any process that is not the Bash tool never reach it. Our own design; the owner's ruling on #1793.
