section: rails-flow
- **The mock-up gate asks the stack which paths a person sees, instead of assuming Rails — `plugins/rails-flow/scripts/check_mockup_gate.py`, `plugins/rails-flow/scripts/detect_stack.py`** (#2219; our own design, no framework claim). A stack declares a per-stack descriptor key `ui_scope` (`paths`, `not_paths`, `seen_anyway` regexes, and a `cases` file that proves them; never merged across plugins, so a Rails app with a Next.js front end has both); the detector validates it and reports it, and the gate calls a file user-visible when SOME detected stack says so (a stack's `not_paths` bind only its own paths). `Story:` classifies through the same list, so a JavaScript front-end project can name a component path. **Fallback, tracked in #2274:** when no installed stack declares `ui_scope` (a Rails project on flow-suite without rails-stack), the gate uses its old built-in Rails-shaped list and prints "no installed stack declares ui_scope: used the built-in Rails-shaped list; install rails-stack or nextjs-stack" on every run; a detector that cannot judge falls back too, saying why. Measured on a downstream Rails repository's 6,752 tracked files: the old list and rails-stack's declaration classify the same 524 files as user-visible. `detect_stack.py` is byte-identical in design-flow and pipeline.
