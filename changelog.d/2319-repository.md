section: Repository hygiene
- **A killed run cleans up after itself first — `scripts/proc_group.py`** (#2319). Our-design change, part of the owner rule of 2026-10-22 on temp dirs (#2306). `kill_tree` walks the tree once, sends SIGTERM to every process and group in it, and waits up to `GRACE_S` (0.5 s), ending early when they are gone. Then comes the #1548 freeze-and-SIGKILL, unchanged except that it starts from everything the first walk saw, so an orphan made during the grace is still killed. SIGKILL runs no handler: one guard run left 5,155 `rf-` dirs that `rf_tmp` could not remove, consistent with about nine mutant runs killed on their timeout under load 40–60 (inferred, 566 dirs per run). It only runs on a timeout or an interrupt, so a normal run pays nothing. New fixtures: a timed-out run removes its `rf_tmp` dir, and an orphan in its own group that ignores SIGTERM is still killed. The #1548 mid-walk fixture runs with `grace=0`, the freeze it tests.
