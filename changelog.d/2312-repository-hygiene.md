section: Repository hygiene
- **`scripts/maintainer_doctor_selftest.py` no longer fails 21 checks on a maintainer's Mac** (#2312). Its fixture repository was made with a plain `git clone` of an empty remote, which carries none of `fixture_git`'s markers. A maintainer's Mac has rails-flow's git shim first on `PATH`, and the shim refuses `git add -A` in a repository that is not marked as a fixture (#1994), so every staging step failed quietly, the fixture had no commits and no `origin/dev`, and 21 checks failed on a message about `origin/dev` that named nothing; CI has no shim, so it passed. Measured: with the shim on `PATH` the selftest failed 21 of 134; it now passes 144 of 144 in the same environment. The fixture is built with `fixture_git.init` plus `git remote add` (the same repository for an empty remote), every build step raises with git's own message when it fails instead of leaving a half-built repository, and a new check builds the fixture in a subprocess under (A) the shipped shim first on `PATH` and (B) a hostile global and system gitconfig, each with a control that proves the environment is hostile (the old build is refused under A; a plain `git init` names the hostile default branch under B). Reverting the build to a plain clone turns check A red.
