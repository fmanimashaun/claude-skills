- **A repository that never wired `project_gates` is refused, not "not applicable" — `plugins/rails-flow/hooks/scripts/lib/pr_ready_guard.py`** (#2304). Until now `guard-pr-ready` (and the `gh` shim behind it) judged a repository only where a workflow names `project_gates.py`, `CLAUDE.md` carries the rails-flow block, or a sweep had run, so in a repository that never wired it every project gate (`docs-layout`, `brain-fresh`, `owner-rulings`, `adversary-review`, ...) was inert and the guard said "not applicable". flo-it-ui is one: its `docs-layout` command exits 1 on 21 misplaced files and nothing ran it. Now `gh pr ready` there is refused with "project gates are not wired" and the way out (`/rails-flow:setup-flow`, §8), and SessionStart prints one `PROJECT GATES NOT WIRED` line (silent where it is wired or opted out). A repository that genuinely runs something else declares it in `.claude/rails-flow/no-project-gates`, one line giving the reason; a file with no reason is not an opt-out. Measured: Retask-platform is wired, flo-it-ui is not, and claude-skills itself (its gates are `scripts/maintainer_doctor.py`) now carries an explicit reasoned opt-out.
