- **A `gh issue create` after `cd <other repo> &&` keeps that repo's label rules when its heredoc body is written to the temp directory — `plugins/rails-flow/hooks/scripts/lib/issue_labels.py`** (#1990). The refused command was `cd ~/projects/Retask-platform && cat > /private/tmp/…/scratchpad/cli.md <<'EOF' … EOF`, followed by the create on a new line. 1.58.0 judged it by the session's taxonomy ("needs one of comp:*"); #1851 corrected the message in 1.59.0, but the create was still refused with "cannot tell which repository", because only a bare relative body filename kept the `cd`. A body written under `/tmp/` or `/private/tmp/`, where the harness scratchpad lives, now keeps it too. Every other absolute path still loses the `cd`, because a git config there can redirect gh's remote: `/etc/gitconfig`, `~/.config/git/config`, and `.git/` anywhere, including inside the temp directory. Covered by fixtures in `check_hook_gates.py` and `issue_labels.py --selftest`: the other repo's rules allow and refuse; the session's repo still needs `comp:*`; writes into `.git/config`, the XDG git config and `/tmp/r/.git/config` lose the `cd`. After the review of #1995: a glob character (`* ? [ ] { } !`) in the path loses the `cd` (`.g*/config`, `.gi[t]`, `[.]git`, `.gi?` all name `.git/config`), and the path is judged by its realpath, which must stay under the temp directory with no `.git` component, so a pre-existing `/tmp` symlink into `.git` or out of `/tmp` loses it too. Selftest rows for six glob spellings and two symlinks; one mutant per rule; 136/136 caught. Our own design; no framework claim.
