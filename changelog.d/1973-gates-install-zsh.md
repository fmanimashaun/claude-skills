section: Repository hygiene
- **CI installs zsh, so `git_shim_selftest.py`'s zsh row runs on the hosted runner too — `.github/workflows/gates.yml`** (#1973, a follow-up). PR #1974's run measured `host tool zsh: ABSENT` on `ubuntu-latest`, so the row ran only on a maintainer's machine and in the Linux check; on CI it was skipped (said, not counted). The `gates` job (the sweep) and each `mutation` shard (the `git_shim` guards) now `apt-get install` zsh and assert it is on PATH, failing the step if the install silently did not happen. `release.yml` calls this workflow (`workflow_call`), so the release sweep gets it with no second copy. The gates job then runs the hook case alone (`git_shim_selftest.py --match`), prints its result, and fails if it says it skipped its zsh row, because the sweep prints only a passing gate's verdict and so could not show the row running. The install is retried once after 5 s, so a mirror blip cannot turn a release red. zsh leaves the `host tool` report line, which runs before the install and would read ABSENT on every run; that line keeps perl and shasum (8b's review). The coordinator's call.
