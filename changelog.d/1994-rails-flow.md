section: rails-flow
- **The git shim's fixture exemption could be impersonated, and `core.hooksPath=/dev/null` switched the pre-commit and pre-push guards off — `plugins/rails-flow/git-shim/git`, `plugins/rails-flow/hooks/scripts/session-start.sh`, `plugins/rails-flow/scripts/fixture_git.py`** (#1994, #1982; found by an adversary pass, five commands got through). The `add` exemption that shipped in v1.157.0 (#1985) trusted `CLAUDE_SESSION_PROJECT_TOP`/`RAILS_FLOW_PROJECT_TOP`, so `RAILS_FLOW_PROJECT_TOP=/usr TMPDIR=<parent> GIT_DIR=<project>/.git GIT_WORK_TREE=<project> git add -A` staged the whole real project. Now: (a) the repository git will really use is asked of the real git (`rev-parse --absolute-git-dir --show-toplevel`, under the real arguments), and the exemption is refused when the command line carries `--git-dir`, `--work-tree`, `-C` or `--namespace`, or the environment carries `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`, `GIT_COMMON_DIR` or `GIT_NAMESPACE`; (b) a repository is a fixture only when it carries `.git/rails-flow-fixture`, which only `fixture_git.init` writes, and a repository the SessionStart hook marked (`.git/claude-session-project`) is never one, whatever the environment says; (c) `core.hooksPath=/dev/null` is admitted only for a command that runs no hook (`status`, `diff`, `log`, `show`, `ls-files`, `rev-parse`, `fetch`, `ls-remote`, `config`, ...), never for `commit`, `push` or any other, and never through a `GIT_CONFIG_GLOBAL` file. The exemption stays `add` only (`reset --hard`, `clean`, forced checkout are refused in a fixture). Still true, by design: the shim is a tripwire against accident, not a boundary, so an agent that can write a file can create the identity file by hand. `classify_door`, `risky_diff` and `git_guard_selftest` fixtures no longer use `reset --hard`. Our own design; the allowlist ruling this corrects is the coordinator's on #1982 (core.hooksPath), recorded on #1994. Accepted cost, documented in the shim and in `plugins/rails-flow/scripts/wip_commit.py`'s usage: `wip_commit.py` commits with hooks off and is therefore refused when run by hand from the Bash tool (its Stop-hook path has no shim on PATH and is unaffected); its `--selftest` under the shim is #1998.
