- **The Stop and SessionStart hooks no longer run a submodule's own clean filter — `plugins/rails-flow/hooks/scripts/lib/where_stopped.py`, `plugins/rails-flow/hooks/scripts/lib/worktree_guard.py`** (#1916). `where_stopped.py` runs every turn and the resume pointer at every session start. Both read `git status --porcelain` with no `--ignore-submodules`, so status recursed into a submodule, and a same-size change made git hash the file through the submodule's own `filter.<name>.clean`, a command the repository chose. That ran before the user could answer anything. Both now pass `--ignore-submodules=all`: a submodule's own state is not this worktree's unsaved work. The trade, stated: a worktree whose ONLY change is a submodule's dirty state or a moved gitlink now reads as clean, so the where-stopped record no longer lists it as unsaved work and the resume pointer may list it as finished. Each call has a fixture with a real gitlink whose config names a marker-writing clean filter plus a same-size change, and a mutant that removes the flag (`where_stopped.py --selftest`; `check_hook_gates.py --only guard_worktree_pointer`). The other `git` calls in both files (`rev-parse`, `rev-list`, `remote`, `branch`, `merge-base`, `worktree list`) read refs and commits and hash no working-tree file. Measured on git 2.50.1. Our own design; no framework claim.
