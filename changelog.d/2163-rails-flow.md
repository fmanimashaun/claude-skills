section: rails-flow
- **One stack detector reads each stack plugin's own markers — `plugins/rails-flow/scripts/detect_stack.py`** (#2163, slice 1 of #2162). `detect_stack.py [project] [--json]` reports every stack a project matches; a project can be several at once (Next.js + Supabase + Vercel). It knows no stack itself.
  Each stack plugin ships a `stacks.json` at its root, declaring its stacks and their markers. A marker is `{"file": path}`, `{"dir": path}` or `{"package_dependency": name}`. A stack matches when every marker in `all` holds and, if it lists `any`, one of those does.
  Manifests are discovered the way `project_gates.py` finds `checks.json`, in a checkout and in the installed cache, plus the repo root, which is `rails-stack`'s source. Two cached versions of one plugin collapse to the higher. `rails-stack` declares Rails in the repo-root `stacks.json`: a project with both a `Gemfile` and `config/application.rb`.
  An unknown marker kind, a stack with no markers, or an unreadable or nameless manifest is exit 2, never a silent no-match. Exit 0 means a stack was detected, 1 none.
  Adding a stack is a new manifest, never an edit to the detector (`.claude/skills/plugin-boundaries` rule 1). The selftest (15 cases) proves that with fixture manifests for stacks no plugin ships yet, a combined project and an empty one, and a mutation guard (`plugins/rails-flow/scripts/mutations/detect_stack.py`, 7 mutations) holds each rule. Our own design (#2162's decisions, maintainer, 2026-10-20), not a framework claim.
