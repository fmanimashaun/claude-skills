section: qa-flow
- **The release gate answers a large command in under a second, and so does its fallback — `plugins/qa-flow/hooks/scripts/release-gate.sh`** (#1952, found by the qa-flow audit). Measured on dev: a command with a push to main took 3.1 s at 195 KB and 8.2 s at 390 KB, and gave no answer in 70 s at 683 KB; with a 3 s deadline even the 390 KB command got none. The cause is the degraded-mode fallback, which runs exactly when the gate is already late and is quadratic in bash 3.2 (`${x//a/b}` passes and a word loop): with no other work in the way, a 2 KB payload took 2 s, 6 KB took 22 s and 11 KB over 40 s. The harness kills a hook at 15 s and a killed hook lets the command run, so for a command of a few KB in a degraded path (a deadline or a missing tool) the gate was not a deny. Now a payload past 128 KB never enters the full path, and the fallback decides any payload past 2 KB, in one way: it REFUSES. Two security reviews and 8b's each found a spelling of the tool name that a word list missed (a verb alias, `g"it"`, `g''it`, `g\it`, `G=gi; ${G}t push`, `$(printf gi)t push`, then `$'\x67it'`, `/usr/bin/g?t`, `g{i,}t`), because the shell gives a command word a hundred spellings and this path cannot run the shell; the one answer that cannot be wrong is the refusal, so the gate does not judge a command that large by its words at all. Both answer in well under a second at any size and honour `QA_ALLOW_MAIN=1` with an audit line. Cost, accepted and said in the refusal: in those cases every command is refused, whatever it contains, and the message says to write the file with the Write tool and run a short command (a command past 128 KB is a file written through Bash; in the degraded paths, a deadline or a missing tool, the limit is 2 KB). Small commands take the unchanged precise path (the 249, 251, 76, 142, 113, 302, 239 and 99 checks of the other release-gate groups still pass). New group `release_gate_large` (14 checks plus 14 for the alias, case, split-word, expansion, ANSI-C, glob and brace shapes, all refused) fails against the old hook; its guard `hook_release_gate_large` has 5 mutants, all caught on macOS and on Linux. A refusal that arrives within seconds is also what makes a harness timeout safe to add on top (#1939).
