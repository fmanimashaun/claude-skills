section: nextjs-stack
- **nextjs-stack declares its security surface for `/rails-flow:secure-design` — `plugins/nextjs-stack/security/nextjs.md` and `plugins/nextjs-stack/security/supabase.md`** (#2210). Two `security` blocks in `plugins/nextjs-stack/stacks.json`, one per stack, so a Supabase project without Next.js still gets its questions. Next.js: Server Functions and Route Handlers as public endpoints, Proxy (formerly Middleware) and what its `matcher` leaves out, `NEXT_PUBLIC_` exposure, `getSession()` on the server; scanner `npm audit`. Supabase: RLS on every table in an exposed schema and the default grants, the `service_role` key, views and `security_invoker`, storage buckets and `storage.objects` policies, Edge Functions with `verify_jwt` off, `security definer`; scanner `supabase db advisors`. Each has `boundary_text` and `boundary_paths` for the stack's spellings and layout (`app/**/route.ts`, `proxy.ts`, `"use server"`, `supabase/migrations/`, `supabase/functions/`), including the Pages Router (`pages/api/`), a monorepo app or package (`apps/<name>/`, `packages/<name>/`), grants to `anon` and `authenticated`, the Supabase Auth client calls (`signUp`, `signInWith*`, `exchangeCodeForSession`, `createServerClient`) and Supabase's SSR helpers (`utils/supabase/`), proved by 54 and 38 cases with a near miss for each. Each checklist question that rests on a framework fact cites its audit row as `(C-n)`, and `detect_stack.py --check` refuses a citation that is not a CONFIRMED row. Every framework claim was verified on 2026-10-21 against nextjs.org/docs (Next.js 16.4.2) and supabase.com/docs, 11 claims all CONFIRMED (7 with corrected wording), each quote matched against the page text by `check_verdict_quotes.py` (#2249): `docs/evidence/audits/2026-10-21-nextjs-security-claims.md`. Corrections recorded there: the Security Advisor's CLI is `supabase db advisors`, not `supabase db lint`; a public bucket skips access checks for reading and serving only; RLS exposure follows role grants, not the anon key directly.
