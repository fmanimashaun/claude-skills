- **The hook-gates harness masks its own scratch-directory prefix, so `--match` works again for labels that embed a fixture directory — `plugins/rails-flow/scripts/check_hook_gates.py`, `scripts/mutations/check_hook_gates_harness.py`** (#1893). The v1.156.0 full sweep failed `mutation coverage` with nine "cannot be narrowed" guards (`hook_worktree_guard` ×7, `hook_worktree_guard_parse` ×2) and one more in `hook_trusted_env`. Cause 1: #1800 moved the fixtures to `tempfile.mkdtemp(prefix="hookgates-")` but the mask that makes the survey's labels comparable with the run's (`_TEMP_PATH`) only knew Python's default `tmp…` names, so a label embedding a scratch path differed on every pass and `--match` refused the group. The prefix is now one constant (`SCRATCH_PREFIX`) used by `scratch_dir()` and by the mask, with a selftest row that masks a path under a real scratch directory (whole, or cut right after the prefix) and a mutant that drops it. Cause 2: two `hostile_env` checks read a view computed by plain code before the previous check, which `--match` skips, so the wanted check saw an empty string; each now computes its own. Replayed alone at `--jobs 1`: `hook_worktree_guard` 18/18 (+1 new mutant in `check_hook_gates_harness`), `hook_worktree_guard_parse` 4/4, `hook_trusted_env` 44/44. Test-only; our own harness, no framework claim.
