- **`check_criteria.py` maps `[security]` criteria to the threat model's `mitigate` rows — `plugins/rails-flow/scripts/check_criteria.py`** (#2118). Our-design change, no external claim. A unit with a threat model (`docs/security/threat-models/<slug>.md`, found beside its acceptance file or via `--threat-model`) is refused when a `mitigate` row (each row's own `ID` cell, `TM-n`, which never changes) has no `[security]` criterion citing it in its citation slot (`(TM-1)` or `covers: TM-1` at the end; a tag or id in an HTML comment or code span does not count), or when a `[security]` criterion cites no row or an `accept`, `transfer` or `eliminate` row. No model, no change; a model with no readable table is exit 2. The `spec-reviewer` agent maps the same rows as `spec-missing` and `spec-unasked`. The default threat model is found at the repository root above the criteria file, wherever it sits, and a criteria file with no model prints that the security check was skipped and why. **Adversary pass:** a threat-model row the reader cannot parse (`**TM-3**`, `TM-3a`, a look-alike hyphen or letter, a blank or qualified decision) refuses the model (exit 2) instead of dropping its requirement; a criterion inside a multi-line or unclosed comment or a fenced block is not live; `check_threat_model.py` counts TM-1 and TM-01 as one ID and refuses a second `## Threats`; the skip note names the other models in the directory.
