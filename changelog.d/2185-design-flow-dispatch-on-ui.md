section: design-flow
- **The design commands dispatch on the project's `descriptor.ui` instead of naming Rails: `/design-flow:setup`, `component`, `port`, `audit`, `mobile`, `tokens` and `variants` resolve the UI adapter with `plugins/design-flow/scripts/ui_adapter.py` and read their stack-specific steps from `plugins/design-flow/ui/viewcomponent-erb/<command>.md`** (#2185). `ui_adapter.py` reads the stack through design-flow's own mirror of the stack detector (`plugins/design-flow/scripts/detect_stack.py`, byte-identical to rails-flow's), so it needs no other plugin installed, and it exits 2 with the reason when the stack is unrecognised, declares no `ui.implementation` or has no adapter here: there is no default adapter. `--implementation <id>` names one by hand. `design_prompt.py` takes its token file from the adapter instead of a Rails default. The README, `plugin.json`, the two agents' sample findings and `compose_brief.py` no longer name a stack. Nothing moved to rails-stack: this is the owner's ruling that design stays neutral, and our own architecture decision, so there is no doctrine-verifier step and no framework claim.
