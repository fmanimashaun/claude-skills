- **A worktree teardown leaves nothing behind, branch included — `plugins/rails-flow/scripts/worktree_teardown.py`** (#2296). Our-design change, no external claim. It follows the owner rule of 2026-10-22, "a teardown worktree should never leave a file or folder behind", and its scope addition: delete the branch, tear down, then clear the context. Measured that day: `claude-skills-wt` held 81 non-worktree folders and 131 loose files (22 GB); `retask-wt` held 68 folders and 183 files (37 GB). The fix:
  - A worktree's artifacts (reviewer exports, baselines, logs) go in its own `<worktree>/.rf-scratch/`, and the teardown removes that dir.
  - The teardown then fails, naming each entry, when anything new was left in the worktrees' parent during the worktree's life. Anything except other worktrees and the KEEP list `_logs`, `_handoff`, `_board`, `_tools` counts.
  - It deletes the merged branch: locally with `git update-ref -d` on the proved tip, and on `origin` with `--force-with-lease` on that tip. The remote delete happens only when no open PR uses the branch as its base or head. An integration branch, origin's default branch and the main checkout's branch are never deleted. Not `git branch -d`, because that judges "merged" against the checkout it runs in: measured 2026-10-22, it refused four merged branches from a stale main checkout.
  - `--audit` lists what no worktree owns in each worktrees' parent, including the conventional `<main>-wt`. `scripts/maintainer_doctor.py` runs it as `nothing beside the worktrees`.
  - `plugins/rails-flow/hooks/session-reset.mjs` clears the context only after a teardown that says it left nothing. A bare `git worktree remove`, a LEFT BEHIND teardown, a refused one and a dry run do not count.
  - **Review:** a branch is deleted only when its tip is proven an ancestor of the integration branch. `--assume-merged` lets a squash-merged worktree be torn down, but its unproven branch is kept and named. A branch checked out in any registered worktree is protected.
