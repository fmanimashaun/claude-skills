- **The toolchain step installs what the detected stack is missing, unattended and fail-closed — `plugins/rails-flow/scripts/toolchain_install.py`** (#2288). Owner direction 2026-10-21: the flows run unattended, so `/rails-flow:toolchain-check` and `/rails-flow:setup-flow` act instead of printing advice. It acts only on what `stack_toolchain.py` (#2168) finds missing for a detected stack, from installed plugins' descriptors. A plugin is installed with `claude plugin install <id> --scope local --json` (this machine only), only from an allowlisted marketplace whose registered source `claude plugin marketplace list --json` confirms, and counts only on exit 0 with `outcome: ok`; each install goes into a restart marker that `--confirm` clears once the plugin is enabled after the restart. A CLI is installed by the descriptor's `auto_install` methods (`npm-global`, `brew-tap`) only after the npm registry's `repository.url` or the tap's remote names the vendor's repository; `npm-dev` is never run but reported as `PR NEEDED`, a reviewed change on its own branch. Tokens come from `.rails-flow/toolchain.env`, read only when git ignores it and does not track it, and are never written anywhere. Everything an agent cannot do is a `BLOCKED` line, filed as a coordination ask with `--session-id`, and the run moves on. Every command runs with #2168's allowlisted probe environment and cwd `/`, every installer must resolve outside the project, and a symlinked marker path is refused. The facts behind it were verified 2026-10-21/22 and quote-checked with `scripts/check_verdict_quotes.py`: the install command, its exit codes and JSON result, local scope, loading after a restart, `marketplace list --json`, `VERCEL_TOKEN`, `SUPABASE_ACCESS_TOKEN`, and `brew install supabase/tap/supabase` (the Supabase CLI README). `detect_stack.py` validates the new `auto_install` and `token` fields.
