section: Repository hygiene
- **A timeout inside an UNMUTATED selftest reads STARVED (not judged), not FAIL: it is retried once, and an all-starved run exits 3 — `scripts/mutation_check.py`, `scripts/mutation_check_selftest.py`, `scripts/mutations/mutation_check_harness.py`** (#2000). On a loaded laptop a selftest's own 20 s git call times out, the selftest records that as its failure and exits 1, and the harness read it as "the unmutated selftest fails": `cannot be narrowed` or INERT, a FAIL, with no mutant ever having survived (three runs of #1994 reported 27, 11 and 8 of 100 failed, every one a `TimeoutExpired`, none a survivor). Now a baseline or a narrowed control whose output says `TimeoutExpired ... timed out after` is run once more; when it is starved again it is listed as `STARV` / NOT JUDGED, and a run in which nothing failed but something was starved exits 3, the code the doctor already treats as a skip (a proof refuses it), never 0 (a pass) and never 1 (a failure). A failure that is not a timeout stays INERT, a survivor stays a failure, and a MUTATED run's timeout is untouched. Selftest rows for the retry, the starved baseline, the starved control, the real failure and the process exit; seven mutants hold them. Our own design; the coordinator's assignment on #2000.
