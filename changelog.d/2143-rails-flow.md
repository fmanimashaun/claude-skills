section: rails-flow
- **A `gh pr ready` refused for "no sweep record for HEAD" now names the worktree that holds a green record, and the one-command way to use it — `plugins/rails-flow/hooks/scripts/lib/pr_ready_guard.py`** (#2143). A session whose Bash tool resets its directory to the main checkout is judged on that checkout's HEAD, and the released way out (`cd <worktree> && gh pr ready <n>`, #2132, in v1.157.6 and rails-flow 1.64.0) was nowhere in the refusal: Retask's coordinator could not find it for #2159. When another worktree of the repository has a green, zero-skip record for its own HEAD, the refusal says so, with that HEAD, the path and `cd <path> && gh pr ready <n>` (or "from a session started in <path>" when the path is not one the cd exception accepts); a red record, a record with a skip, one for another head and one whose `skips` is not a number are never offered. Nothing is loosened: the main checkout is still refused, by the hook and by the `gh` shim. The measurement behind it, on the released 1.64.0 hook and shim: the `cd` form is allowed, a bare `gh pr ready` from a reset directory is refused as designed. The search is bounded (review of #2293): it reads `git worktree list --porcelain -z`, so a path holding a newline is one path and is shown escaped, and it stops after `RAILS_FLOW_HINT_MAX_WORKTREES` (20) worktrees or `RAILS_FLOW_HINT_BUDGET` (4 s), saying so in the refusal.
